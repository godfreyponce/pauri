# Glass Window and Transparency Slider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The panel is frosted glass, so the apps behind it show through blurred, and one slider in the settings popover sets how see-through it is, live, saved across relaunches.

**Architecture:** `PanelController` puts an `NSVisualEffectView` (behind-window blur) under the existing SwiftUI hosting view. `PanelView` lays a solid window-colored tint over that glass; the tint's opacity is `1 - transparency`. `transparency` is one `@AppStorage` value in `UserDefaults`, read by `PanelView` and written by a `Slider` in the existing `SettingsView` popover. `@AppStorage` makes the change live and saves it.

**Tech Stack:** Swift 6.2 (Command Line Tools), SwiftPM, SwiftUI, AppKit. No third-party dependency.

**Spec:** `docs/spec.md` decision 16; issue #9.

## Gate 1 decisions (owner: change any of these before go)

1. **Glass = `NSVisualEffectView`, material `.popover`, blending `.behindWindow`, state `.active`.** This is the classic macOS frosted window background (Finder sidebar, Spotlight style). It works on macOS 14, the package's floor. `.popover` follows light and dark mode. Alternatives: (a) `.hudWindow`, more see-through but always dark, so dark text in light mode would be hard to read; (b) `.sidebar` or `.menu`, other adaptive blurs; (c) macOS 26 Liquid Glass (`NSGlassEffectView`, in this SDK). Liquid Glass needs an `if #available(macOS 26, *)` branch plus a macOS 14 fallback, two looks to maintain. Apple aims it at controls that float over content, not at whole window backgrounds. Changing the material is a one-word swap in Task 1.
2. **The slider runs from Solid (0) to Glass (1), default Glass (1).** At 1 the tint is gone and you see the bare system material. At 0 the window color covers it fully. The slider never goes past the system material toward clearer glass. That keeps "readable at the most see-through setting" true by Apple's design of the material, with no invented floor value. The cost: you cannot make it clearer than the material. If you want clearer, the slider would also have to fade the glass layer, and the plan would need a minimum value, which would be a guess checked by eye.
3. **No 4-variant visual pass.** The look is fixed by spec decision 16 (macOS glass material), and the slider is a stock SwiftUI row in the popover #12 built. An HTML page cannot show real behind-window blur, so variants would compare CSS imitations of the thing being decided. #1 and #12 made the same call. Say no here and Task 1 starts with a variants page in `design-directions/issue-9.html` instead, references first.
4. **Readability is checked by hand, with no chat text yet.** Chat text arrives with #2. Today the text directly on the glass is the gear icon and the popover. The text field draws its own background, so its text stays readable at any setting. Task 3 checks what exists today over a busy background. It also leaves a comment on #2 so that #2's gate 2 checks its answer text at the Glass end.
5. **No new automated test.** The behavior is a material, a color, and `@AppStorage` saving a Double. A test would pin `1 - transparency` or re-test `UserDefaults`. The hand checks in Task 3 cover all three Done-when items. The existing suite stays green.

## Global Constraints

- One slider, no other appearance settings (ticket constraint).
- Native AppKit and SwiftUI inside the existing `NSPanel`. No third-party package.
- No `NSApp.activate`: the app behind stays active (#1).
- `PanelView`'s key-focus filter (`note.object is FloatingPanel`) stays as is. The popover must still open and stay open.
- Commit format: `type(scope): summary (refs #9)`. Trailers: the harness default `Co-Authored-By` line, nothing else.

## Review Focus

1. **Inactive app, flat glass.** Pauri never becomes the active app. With the default `state` (`.followsWindowActiveState`) the effect view can draw its flat, non-blurred inactive look. Expected: `state = .active` keeps it frosted. Hand check 1 in Task 3.
2. **Titlebar strip.** The panel is `.titled` with `.fullSizeContentView`. Expected: the glass and the tint both reach the top edge, with no solid band where the hidden title bar is (`ignoresSafeArea` on the tint). Hand check 1.
3. **Live change through the popover.** The slider lives in the popover's own window, and `PanelView` reads the same `@AppStorage` key. Expected: the panel changes while the slider is dragging, not only after the popover closes. Hand check 2.
4. **Dark and light mode.** Expected: the tint (`windowBackgroundColor`) and the `.popover` material both follow the system appearance. Hand check 3.

- [ ] **Step 1: Put the glass under the hosting view.** In `PanelController.init`, replace `panel.contentView = NSHostingView(rootView: PanelView(hotKey: hotKey))` with:

```swift
let glass = NSVisualEffectView()
glass.material = .popover
glass.blendingMode = .behindWindow
// Pauri never becomes the active app; following the active state would draw the flat inactive look.
glass.state = .active
panel.contentView = glass
let content = NSHostingView(rootView: PanelView(hotKey: hotKey))
content.frame = glass.bounds
content.autoresizingMask = [.width, .height]
glass.addSubview(content)
```

`panel.contentView = glass` comes before `content.frame = glass.bounds`, so the bounds are already the panel's size.

- [ ] **Step 2: Add `Transparency`** (block above) to `Sources/Pauri/Settings.swift`, after the imports.
