# #42 Menu bar item with the Orbit P logo: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While Pauri runs, the Orbit P glyph sits in the menu bar. A left click shows or hides the panel exactly as the hotkey does, and a right-click (or Control-click) opens a menu with Quit Pauri.

**Architecture:** One task. The glyph ships as an SVG in `Support/`, and `scripts/build-app.sh` copies it into the bundle next to the Blossom files. `AppDelegate` (`PauriApp.swift`) makes one `NSStatusItem` after the panel exists. The button's image is the SVG loaded by `NSImage`, set to 16 pt tall and `isTemplate = true`. The button's action reads the current event: a right-click or Control-click pops the one-item menu, and any other click calls the same method the hotkey calls. `PanelController` does not change.

**Tech Stack:** Swift 6, AppKit `NSStatusItem` and `NSMenu`, `NSImage` SVG loading (`_NSSVGImageRep`), macOS 14 minimum.

**Spec:** Issue #42 (no comments). No design spec in `docs/superpowers/specs/`. The glyph was picked by the owner on 2026-11-18, so the visual rule's variant step is already done and this plan draws no variants.

## What is known (planning session, read-only)

- Today `AppDelegate.hotKeyPressed()` (`PauriApp.swift:35-43`) is the whole toggle: hide when `panel.isKey`, else read the selection, then `panel.show()`. Its doc says it is the only place the selection is read. `PanelController.show()` never calls `NSApp.activate`, so the app behind stays active.
- A click on a status item does not activate the app, so `NSWorkspace.shared.frontmostApplication` is still the app behind and `SelectionGrabber.selectedText()` reads its selection on a click, as it does on the hotkey.
- The Blossom SVGs load the same way this glyph will: `Bundle.main.url(forResource:withExtension: "svg").flatMap(NSImage.init(contentsOf:))` (`ModelPicker.swift:15-17`), copied by `build-app.sh:24`.
- **Probe run in planning (scratch script, nothing in the repo):** on this Mac, `NSImage(contentsOf:)` loads the glyph as `_NSSVGImageRep`, and it honors a cropped `viewBox="18 14 96 102"` (natural size 96 x 102). Drawn at 16 pt tall, it fills a 16 x 16 px bitmap at 1x and 31 x 32 px at 2x, edge to edge, so no padding is baked in. The 2x render is clean. The 1x render is soft: the stem is 20/102 x 16 = 3.1 px wide, so its edges fall between pixels.
- Settings is a popover anchored to the gear inside the panel (`PanelView.swift:90`). Check for Updates is the header button in the panel, and its only feedback (spinner, check-mark) is drawn in the panel (`PanelView.swift:301`). Pauri's Sparkle user driver shows no dialogs of its own.
- `Updater.showPanelAfterUpdateKey` is `PauriShowPanelAfterUpdate`. Setting it with `defaults write` before a launch drives the same `panel?.show()` path a real update relaunch does.

## Gate 1 decisions (owner: change any of these before go)

1. **Left click toggles the panel, like the hotkey.** It calls the hotkey's method, so the rule is the same: hide when the panel has focus, else read the selection and show. The ticket's ELI5 says "open it with a click", and the Done-when ties the click to the hotkey's behavior. Alternative: a left click opens a menu (Show Pauri, Quit), as ChatGPT's blossom does; Quit is then easier to find, but opening Pauri takes two clicks.
2. **Right-click or Control-click opens the menu, and the menu holds only "Quit Pauri" (Cmd+Q shown).** Show Pauri is the left click. Settings and Check for Updates already live in the panel, and both show their result only there; a menu item for them would need new plumbing to open the panel and then the popover or check. Alternative: add "Show Pauri" above Quit, for people who never left-click a menu bar icon.
3. **Asset format: SVG, loaded by `NSImage`, the same path as the Blossom.** The probe above shows it renders on macOS and stays vector at every scale. No PDF or PNG export step, and no new tool. The asset is the owner's SVG with one change: `viewBox="0 0 128 128"` becomes `viewBox="18 14 96 102"`, the glyph's own bounds, so the asset has no padding (Bjango). The drawing itself is unchanged.
4. **Size: 16 pt tall, width from the aspect (16 x 96 / 102, about 15.06 pt).** The ticket's "about 16pt tall" wins over its "18pt" probe size. **1x risk:** at 1x the stem's edges are soft (3.1 px). The builder shows 1x and 2x renders at gate 2. If you find 1x too soft, the fix is a hand-tuned 1x PNG, filed as its own ticket, not done here.
5. **`hotKeyPressed()` is renamed `togglePanel()`.** The hotkey and the click both call it now, so the old name would be wrong. Three lines change; the behavior does not.
6. **No new unit test.** Every line this ticket adds is AppKit glue (status item, menu, click routing). A test of it would pin the code, not the behavior. The proof is the hand checks in Step 5, and the full suite must still pass.
7. **README's `## Build` list gets two line edits** (click the P to show the panel; right-click it to quit), because that list is where a user learns how to show and quit Pauri. Done-when names only `docs/spec.md`; drop the README edit if you want the ticket narrower.

## Global Constraints

- Pauri stays `LSUIElement`: no Dock icon. `Support/Info.plist` does not change. (#42)
- No remote assets: the glyph ships in the app bundle. (#42)
- Template image: `isTemplate = true`, drawn in solid black only (template images use only the alpha channel). (#42)
- About 16 pt tall inside the 22 pt menu bar, centered, no padding baked into the asset. (#42, Bjango "Designing macOS menu bar extras")
- The panel never activates Pauri: no `NSApp.activate` is added. (`PanelController.show()`)
- The hotkey, Esc to hide, and the relaunch-after-update panel keep working. (#42 Done-when)
- Public repo: no env values, credentials, or owner personal data in commits or issues. (STATE.md gotcha)

## Review Focus

1. **A click on the glyph while the panel has focus** must hide it, not show it again. That works only if the click leaves the panel the key window (a status bar window cannot become key, so it should). Pinned by Step 5 hand check H2. If the panel shows again instead, stop and report; do not switch to a visibility toggle without the owner, because that changes the hotkey-equal behavior the Done-when asks for.
2. **A click while another app has focus and the panel is open behind it** brings the panel forward with that app's selection, as the hotkey does. Pinned by H3.
3. **Right-click must never toggle the panel**, and Control-click must count as a right-click. Pinned by H4.
4. **Quit with a chat mid-answer or the codex child running** ends Pauri. The `codex app-server` child Pauri started should exit with it (its stdin closes). Pinned by H5; if the child stays alive, file a new issue, do not fix it here.
5. **Light and dark menu bars, and a menu bar over a light or dark wallpaper:** the glyph must take the menu bar's color, never draw solid black on dark. Pinned by H1.
