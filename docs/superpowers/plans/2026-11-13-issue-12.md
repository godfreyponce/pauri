# Configurable Hotkey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user records a new show/hide shortcut from inside the panel; it works at once and after a relaunch, and Option+Space is allowed.

**Architecture:** `Shortcut` learns three things: build itself from a key press, name itself (`⌥Space`), and save to and load from `UserDefaults`. `HotKey` becomes the one owner of the live shortcut: it loads the saved one at launch, and can pause, resume, and switch the Carbon registration. A gear button in the panel opens a popover with one recorder button that drives `HotKey`.

**Tech Stack:** Swift 6.2 (Command Line Tools), SwiftPM, SwiftUI, AppKit, Carbon HIToolbox, Observation, Swift Testing. No third-party dependency.

**Spec:** `docs/spec.md` decision 4; issue #12.

## Data flow

```text
                     ~/Library/Preferences/io.github.godfreyponce.pauri.plist (new)
                        UserDefaults key "hotKey" = {keyCode, modifiers}
                          |                                   ^
                          | Shortcut.saved(in:) at launch     | Shortcut.save(to:) on a successful change
                          v                                   |
Sources/Pauri/PauriApp.swift (changed) --> HotKey (changed) --+--> Carbon RegisterEventHotKey
                                             ^
                                             | pause() / resume() / change(to:)
                                             |
Sources/Pauri/PanelView.swift (changed) --> gear --> Sources/Pauri/Settings.swift (new)
                                                     SettingsView + ShortcutRecorder
                                                     (NSEvent local keyDown monitor while recording)
```

Before this ticket the running app read and wrote no files.

## Gate 1 decisions (owner: change any of these before go)

1. **The setting lives in a popover from a small gear button in the panel's top-right corner.** Pauri is `LSUIElement`: no Dock icon, no menu bar, so a Settings window has no natural door. Alternatives: (a) a menu bar icon with "Settings…" and "Quit" (adds a permanent icon the spec does not ask for); (b) Cmd+, opening the SwiftUI `Settings` window (the panel is non-activating and floats above it, so the window could open behind the panel or not at all; not probed).
2. **No 4-variant visual pass.** The gear and popover are stock SwiftUI controls (`Button` with SF Symbol `gearshape`, `.borderless`; a `Form` row in the popover). Same call as #1's gate 1 decision 2: the look belongs to the spec's Fog item "a design-directions pass once the bones work". Say no here and Task 2 starts with the variants page in `design-directions/issue-12.html` instead.
3. **A shortcut needs Command, Option, or Control.** Shift alone or no modifier is refused, because it would swallow normal typing in every app. Esc while recording cancels. Any other key with a required modifier is taken as is.
4. **Lockout guard: opening Pauri again shows the panel.** The setting lives inside the panel, so a shortcut that another app or macOS eats (for example Cmd+Space) would lock the user out. `applicationShouldHandleReopen` shows the panel, so `open build/Pauri.app` (or a Spotlight launch) while it runs always gets you back in. If Carbon refuses a new shortcut outright, the old one is kept and the popover says so.
5. **Option+Space registers on this Mac.** Probed 2026-11-13 on macOS 26.5.2 with a throwaway Carbon program: `RegisterEventHotKey` returned `0` for Option+Space, Option+Shift+K, Option+F13, and Ctrl+Option+Space, while ChatGPT Classic was running. So registration does not report clashes with ChatGPT or with system shortcuts. Which app gets the press when both hold Option+Space is not known; the gate 2 hand check runs with ChatGPT Classic quit.
6. **Saved as one `UserDefaults` key, `hotKey`, holding `["keyCode": Int, "modifiers": Int]`** (Carbon virtual key code and Carbon modifier mask, the same numbers `Shortcut` already holds). Missing or malformed reads as `Shortcut.default`. Reset by hand: `defaults delete io.github.godfreyponce.pauri hotKey`.

## Global Constraints

- The default stays Cmd+Shift+Space (`Shortcut.default`, set by #1). The existing test `defaultShortcutIsNotOptionSpace` stays and stays green.
- Native Swift, SwiftUI inside the existing `NSPanel`. No third-party package (a shortcut-recorder package would also need its resource bundle copied by `scripts/build-app.sh`).
- Carbon `RegisterEventHotKey` stays the registration path. No Accessibility permission, no event tap.
- No `NSApp.activate`: the app behind stays active (Review Focus 1 of #1).
- Commit format: `type(scope): summary (refs #12)`. Trailers: the harness default `Co-Authored-By` line, nothing else.

## Review Focus

1. **The current shortcut pressed while recording.** Carbon eats a registered hotkey before the app sees it, so without care, pressing the current shortcut in the recorder hides the panel. Expected: the recorder pauses the hotkey while recording and resumes it on cancel or close. Hand check 3 in Task 4.
2. **The popover closed mid-record** (click outside, panel hidden). Expected: recording stops, the key monitor is removed, and the old shortcut works again. Hand check 3 in Task 4.
3. **Popover takes key focus.** `PanelView` sets `focused = true` on every `NSWindow.didBecomeKeyNotification`; its comment says the panel is the only window that can become key, which a popover breaks. Expected: the filter in Task 2 Step 2 limits it to the panel, so the popover is not yanked closed. Hand check 1 in Task 4.
4. **Caps Lock on, or keys that carry `.function`/`.numericPad` flags (arrows, F-keys).** Expected: only Cmd, Option, Control, and Shift count. Test `recordingIgnoresOtherFlags` in Task 1.
5. **A shortcut that registers but never arrives** (taken by macOS or another app). Expected: the user gets back in by opening Pauri again (gate 1 decision 4). Hand check 4 in Task 4.

### Task 1: `Shortcut` records, names, and persists itself

**Files:**
- Modify: `Sources/Pauri/HotKey.swift` (the `Shortcut` struct, lines 1-10)
- Test: `Tests/PauriTests/ShortcutTests.swift`

**Interfaces:**
- Produces, all on `Shortcut` in `Sources/Pauri/HotKey.swift` (add `import AppKit` for `NSEvent.ModifierFlags`):
  - `init?(keyCode: UInt16, flags: NSEvent.ModifierFlags)` — nil unless `flags` holds `.command`, `.option`, or `.control`. Maps `.command`→`cmdKey`, `.option`→`optionKey`, `.control`→`controlKey`, `.shift`→`shiftKey`; every other flag is ignored.
  - `var displayName: String` — modifier symbols in the order `⌃⌥⇧⌘`, then the key name. Key names: a table for non-printing keys (`kVK_Space` "Space", Return "↩", Tab "⇥", Delete "⌫", Forward Delete "⌦", Escape "⎋", the four arrows "←→↑↓", F1-F20 "F1".."F20"); any other key goes through `UCKeyTranslate` on `TISCopyCurrentKeyboardLayoutInputSource()`'s `kTISPropertyUnicodeKeyLayoutData`, uppercased; fall back to `"Key \(keyCode)"` if that yields nothing.
  - `static func saved(in defaults: UserDefaults) -> Shortcut` — reads key `"hotKey"` (gate 1 decision 6); `.default` when absent or malformed.
  - `func save(to defaults: UserDefaults)` — writes `["keyCode": Int(keyCode), "modifiers": Int(modifiers)]` under `"hotKey"`.

### Task 2: Change the hotkey from the panel

**Files:**
- Modify: `Sources/Pauri/HotKey.swift` (the `HotKey` class)
- Modify: `Sources/Pauri/PauriApp.swift`
- Modify: `Sources/Pauri/PanelController.swift`
- Modify: `Sources/Pauri/PanelView.swift`
- Create: `Sources/Pauri/Settings.swift`

**Interfaces:**
- Consumes (Task 1): `Shortcut.init?(keyCode:flags:)`, `displayName`, `saved(in:)`, `save(to:)`.
- Produces, on `@MainActor @Observable final class HotKey` (import `Observation`; mark `action`, `handler`, `ref`, `defaults` `@ObservationIgnored`):
  - `private(set) var shortcut: Shortcut`
  - `init(defaults: UserDefaults = .standard, action: @escaping @MainActor () -> Void)` — `shortcut = Shortcut.saved(in: defaults)`, installs the Carbon handler once (as today), then registers.
  - `func pause()` — `UnregisterEventHotKey` the current ref, set it nil.
  - `func resume()` — register `shortcut` again.
  - `@discardableResult func change(to new: Shortcut) -> Bool` — unregister; try `new`; on `noErr` set `shortcut = new`, `new.save(to: defaults)`, return true; on failure re-register the old `shortcut`, log with the existing `NSLog` line, return false.
  - Keep one private `register(_ shortcut: Shortcut) -> Bool` used by all three; it keeps the existing signature/id code.
- Produces in `Sources/Pauri/Settings.swift`:
  - `struct SettingsView: View` with `let hotKey: HotKey` — a `Form` with one row: `LabeledContent("Show or hide Pauri") { ShortcutRecorder(hotKey: hotKey) }`, padded, fixed width about 320 pt.
  - `struct ShortcutRecorder: View` with `let hotKey: HotKey`.

- [ ] **Step 3: `ShortcutRecorder`**

State: `recording: Bool`, `monitor: Any?`, `failed: Bool`.
- Idle: a `Button(hotKey.shortcut.displayName)`. Click → `hotKey.pause()`, `failed = false`, `recording = true`, install `NSEvent.addLocalMonitorForEvents(matching: .keyDown)`.
- Recording: the button reads `"Type shortcut"`; a caption below reads `"Use ⌘, ⌥, or ⌃. Esc cancels."`.
- Monitor handler (runs on main; wrap in `MainActor.assumeIsolated` if Swift 6 demands it): Esc with none of Cmd/Option/Control → stop with nil. `Shortcut(keyCode: event.keyCode, flags: event.modifierFlags)` non-nil → stop with it. Anything else → keep recording. Always return `nil`, so no key leaks into the panel while recording.
- Stop: remove the monitor, `recording = false`; with a shortcut, `failed = !hotKey.change(to:)`; with nil, `hotKey.resume()`.
- `.onDisappear`: if recording, stop with nil (Review Focus 2).
- When `failed`: caption `"Couldn't use that shortcut. The old one still works."`.
