# Send the Selected Text Implementation Plan (refs #6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the hotkey opens Pauri, the text selected in the front app shows as a small removable chip above the input, and sending puts that text in the question. Pauri asks for Accessibility access once, with a one-line reason, and works as before without it.

**Architecture:** The hotkey handler in `AppDelegate` reads the selection before it shows the panel. `SelectionGrabber` (new) asks the frontmost app's focused element for `kAXSelectedTextAttribute` through the Accessibility API, and returns nil when Pauri has no access or nothing is selected. The text goes into a new `Chat.selection` property. `SelectionBar` (new SwiftUI view, above the text field) shows either the one-time access row or the chip. `Chat.send` puts the selection above the question as a Markdown quote and clears it.

**Tech Stack:** Swift 6 (Command Line Tools), SwiftPM, SwiftUI, AppKit, ApplicationServices (Accessibility API), Swift Testing. No third-party dependency.

**Spec:** `docs/spec.md` decision 10 (selected-text half only; the screenshot is #7); issue #6.

## Gate 1 decisions (owner: change any of these before go)

1. **The reason comes first, in the panel. The macOS dialog comes second.** While Pauri has no access and has not asked yet, a row above the text field reads: "To attach the text you select, Pauri needs Accessibility access." with the buttons **Allow** and **Not now**. Allow opens the macOS dialog ("Pauri would like to control this computer using accessibility features"). macOS fixes that wording, and an app cannot add its own reason to it. Either button sets `askedForSelectionAccess`, and the row never comes back. A no (Not now, or Deny in the macOS dialog) leaves Pauri as it is today, with no chip. To turn it on later, the user goes to System Settings > Privacy & Security > Accessibility. There is no Settings toggle for it. Alternative: open the macOS dialog on the first hotkey press with no row. That is fewer parts, but the dialog then jumps over the panel with macOS's generic text and no reason from Pauri.
2. **The selection goes to Codex as a Markdown quote above the question**, as one text input: each selected line gets `> ` in front, then one blank line, then the question. The transcript shows that same full text in bold as the question, so a live chat and a resumed chat look the same (`ResumeReply.exchanges` joins the user message's text parts). Alternative: keep the quote out of the transcript and show it as a gray line. A resumed chat would then have to parse the quote back out of the text, or the two views would differ.
3. **Each hotkey press that shows the panel replaces the chip with what is selected now, or with nothing.** A chip from an earlier press never stays. Alternative: keep the old chip when nothing is selected. That saves re-selecting after a click away, but it can send old text with a new question without the user seeing it.
4. **A question is still required.** A selection with an empty draft does not send (the orb stays dim, as today). Alternative: allow sending the selection alone.
5. **No 4-variant visual pass.** The chip is a stock SwiftUI row: SF Symbol `text.quote`, the first line of the selection cut to one line, and an `xmark.circle.fill` button, on a `.quaternary` capsule. The access row is plain text with two `.borderless` buttons. Same call as #1, #3, #9, and #12: the look belongs to the spec's Fog item "a design-directions pass once the bones work". Say no here and Task 2 starts with the variants page in `design-directions/issue-6.html`, references first.
6. **No size limit on the selection.** No receipt for any number. A select-all on a long document goes to Codex whole.

## Global Constraints

- Selected text only. The screenshot is #7 (issue Constraints).
- Nothing is read until the hotkey is pressed. Only the hotkey path calls `SelectionGrabber.selectedText()`. Not the reopen path (`applicationShouldHandleReopen`), not a timer, and not an observer (Done when, item 4). The `AXIsProcessTrusted()` check reads no app content.
- The hotkey press that hides the panel reads nothing.
- No `NSApp.activate`. The app behind stays the active app (#1). This also keeps the frontmost app the one the user selected in.
- No pasteboard trick (simulated Cmd+C). It would overwrite the user's clipboard.
- `Support/Info.plist` does not change. Accessibility has no usage-description key, unlike the camera or the microphone. The issue's guess was wrong.
- No literal `kAXTrustedCheckOptionPrompt`. In Swift 6 language mode it is a global `var` and does not compile ("not concurrency-safe"). Use the key string `"AXTrustedCheckOptionPrompt"`.
- Test files import `AppKit`, not `Foundation`. Command Line Tools have no `_Testing_Foundation` overlay (#12 history).
- Public repo: no selection text in `NSLog`.
- Commit format: `type(scope): summary (refs #6)`. Trailers: the harness default `Co-Authored-By` line, nothing else.

## Review Focus

1. **Every rebuild loses the Accessibility grant.** `build/Pauri.app` is ad-hoc, linker-signed (`codesign -dv`: `flags=0x20002(adhoc,linker-signed)`, `Info.plist=not bound`). macOS ties the grant to that exact binary, so after a rebuild the System Settings switch still shows on, but `AXIsProcessTrusted()` returns false. Expected: Pauri acts as if access was refused (no chip, no crash). The hand checks reset the grant with `tccutil reset Accessibility io.github.godfreyponce.pauri` before each run. Hand check 1 in Task 3.
2. **Safari web pages.** On a web page the focused element is the `AXWebArea`. Expected: it answers `AXSelectedText`. If hand check 2 shows no chip in Safari, stop and report at gate 2. Do not add the WebKit text-marker fallback (`AXSelectedTextMarkerRange` + `AXStringForTextMarkerRange`) unless the owner asks. Hand check 2 in Task 3.
3. **Hotkey while the panel is visible but not key** (the user clicked into another app and selected there). Expected: the press reads that app's selection and shows the panel, and the chip shows the new text. Hand check 4 in Task 3.
4. **Selection with Windows line endings, blank lines, or space around it.** Expected: the text is trimmed. A selection that is only whitespace counts as nothing. Every line, blank ones too, gets the quote mark. Tests `blankSelectionIsNothing`, `selectionIsTrimmed`, `promptQuotesEveryLineAboveTheQuestion` in Task 1.
5. **A front app that does not answer** (hung). Expected: the hotkey waits for the system's default Accessibility timeout, then opens the panel with no chip. No timeout of our own (no receipt for a number). Not tested. Noted here so gate 2 knows it is a known gap.

### Task 1: The selection goes out with the question

**Files:**
- Create: `Sources/Pauri/SelectionGrabber.swift` (`cleaned` only; Task 2 adds the rest)
- Modify: `Sources/Pauri/Chat.swift` (`selection` property, `prompt`, `send`)
- Test: `Tests/PauriTests/SelectionTests.swift` (new)

**Interfaces:**
- Produces:
  - `enum SelectionGrabber` with `static func cleaned(_ raw: String?) -> String?`. It trims whitespace and newlines at both ends and returns nil for nil or an empty result.
  - On `Chat`: `var selection: String?` (settable, observed). It holds the text for the next question.
  - On `Chat`: `nonisolated static func prompt(_ question: String, selection: String?) -> String`. With a nil selection it returns `question` unchanged. Otherwise it returns each line of `selection` with `"> "` in front, joined by `"\n"`, then `"\n\n"`, then `question`. Split lines with `split(omittingEmptySubsequences: false, whereSeparator: \.isNewline)`, so `"\r\n"` (one `Character`) counts as one line break.
  - `Chat.send(_:)` keeps its signature. On an accepted send it builds `prompt(question, selection: selection)`, sets `selection = nil`, appends `Exchange(question: prompt, answer: "")`, and calls `client.ask(prompt)`. A refused send (blank question, or answering) leaves `selection` as it is.

### Task 2: The hotkey reads the selection; the panel shows the chip and the access row

**Files:**
- Modify: `Sources/Pauri/SelectionGrabber.swift` (Accessibility read and access request)
- Create: `Sources/Pauri/SelectionBar.swift` (chip and access row)
- Modify: `Sources/Pauri/PanelView.swift` (one `SelectionBar(chat: chat)` line, directly above the input `HStack`)
- Modify: `Sources/Pauri/PanelController.swift` (`isKey` replaces `toggle()`)
- Modify: `Sources/Pauri/PauriApp.swift` (`hotKeyPressed()`)
- Modify: `README.md` (`## Build`)

**Interfaces:**
- Consumes (Task 1): `Chat.selection`, `SelectionGrabber.cleaned(_:)`.
- Produces:
  - `SelectionGrabber.isAllowed: Bool` (static) returns `AXIsProcessTrusted()`.
  - `SelectionGrabber.requestAccess()` (static) calls `AXIsProcessTrustedWithOptions(["AXTrustedCheckOptionPrompt": true] as CFDictionary)` and ignores the result.
  - `SelectionGrabber.selectedText() -> String?` (static) returns nil unless `isAllowed`. Otherwise: `NSWorkspace.shared.frontmostApplication?.processIdentifier`, then `AXUIElementCreateApplication(pid)`, then copy `kAXFocusedUIElementAttribute`, then copy `kAXSelectedTextAttribute` from that element as `String`. The result goes through `cleaned`. Any AX error gives nil. No timeout change.
  - `PanelController.isKey: Bool` returns `panel.isKeyWindow`. Remove `toggle()`, because its only caller moves to `AppDelegate`. Keep its doc comment's meaning on the new method.
  - `AppDelegate.hotKeyPressed()`: if `panel.isKey`, hide. Otherwise set `chat.selection = SelectionGrabber.selectedText()` (gate 1 decision 3: always replace, nil too), then `panel.show()`. `HotKey`'s closure calls this method.
  - `struct SelectionBar: View` with `let chat: Chat` and `@AppStorage("askedForSelectionAccess") private var asked = false`:
    - If `!asked && !SelectionGrabber.isAllowed`: the access row. The text is exactly `To attach the text you select, Pauri needs Accessibility access.`, with buttons **Allow** (`asked = true; SelectionGrabber.requestAccess()`) and **Not now** (`asked = true`).
    - Else if `let text = chat.selection`: the chip (gate 1 decision 5). Its `.help(text)` shows the whole selection on hover. The x button has `.help("Remove")` and sets `chat.selection = nil`.
    - Else: nothing (an `EmptyView` or a nil branch, so the layout matches today's).
