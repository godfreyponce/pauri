# Rebuilds Keep Their Permissions: Sign Every Build With One Self-Signed Certificate Implementation Plan (refs #27)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `scripts/build-app.sh` signs `build/Pauri.app` with the owner's `Pauri Self-Signed` certificate when the keychain has it, and ad-hoc when it does not, and prints which. A signed build keeps the same identity on every rebuild, so macOS keeps Pauri's four permissions.

**Architecture:** One `codesign` call at the end of `build-app.sh`, after every file is in the bundle. The script looks up the certificate by name with `security find-identity -p codesigning`. Its designated requirement then reads `identifier "io.github.godfreyponce.pauri" and certificate leaf = H"<cert hash>"`, which stays the same across rebuilds. An ad-hoc build's requirement is its `cdhash`, which changes with every build; this is why macOS drops the grants today.

**Tech Stack:** POSIX `sh`, `codesign`, `security`, `/usr/bin/openssl` (LibreSSL, ships with macOS) for the owner's one-time steps. No new dependency.

**Spec:** issue #27. Decisions 2 and 12 of #26.

## Data flow

```text
login keychain ("Pauri Self-Signed" identity, made once by the owner)
        |
        |  security find-identity -p codesigning   (new read)
        v
scripts/build-app.sh (changed) --> swift build --> build/Pauri.app (binary, Info.plist, SVGs)
        |
        |  codesign --force --sign "Pauri Self-Signed"   (new; when found)
        |  codesign --force --sign -                     (new; when not found)
        v
build/Pauri.app/Contents/_CodeSignature/CodeResources + signed binary (new)
        |
        v
stdout: "Signed with ..." or "Signed ad-hoc ..." (new), then "build/Pauri.app" (unchanged, last line)
```

## Proven before planning (scratch keychain, 2026-11-16)

These were run on the owner's Mac in a throwaway keychain, now deleted. The login keychain was not changed.

- An unsigned bundle with a linker-signed binary fails `codesign --verify --strict` with `code has no resources but signature indicates they must be present`. Today's build is in this state.
- A self-signed certificate made with the `openssl` lines in "Owner's one-time steps" imports with `security import`. It shows in `security find-identity -p codesigning` as `"Pauri Probe Libre" (CSSMERR_TP_NOT_TRUSTED)`, and under **Valid identities only** it does not show at all.
- `codesign --force --sign "<name>"` signs with that untrusted certificate. `codesign --verify --strict` passes, and the designated requirement is `identifier "io.github.godfreyponce.pauri" and certificate leaf = H"..."`. No "Always Trust" step is needed.
- With an **expired** self-signed certificate, `codesign` fails with `<name>: no identity found`, and `find-identity` still lists it as `(CSSMERR_TP_CERT_EXPIRED)`.
- `codesign --force --sign -` (ad-hoc) on the bundle passes `codesign --verify --strict`.
- At planning time the login keychain has no `Pauri Self-Signed` identity.

## Global Constraints

- No paid Developer ID and no notarization. (#27 Constraints, #26 Fog)
- The certificate's private key never goes in the repo, an issue, or a log. The script finds the certificate by its name in the keychain. (#27 Constraints)
- No version change: `Support/Info.plist` stays at 0.1.0 / 1. (#27 Constraints)
- No change to the app's behavior or look. So: no `--options runtime` (hardened runtime would block the microphone without an entitlement), no entitlements file, no `--deep`, no other `Info.plist` key.
- The build's last stdout line stays `build/Pauri.app` (AGENTS.md's full check reads it).
- The certificate name is public: it is in the signature of every app that ships. It holds no personal data: `Pauri Self-Signed`.
- Public repo: no env values, credentials, or owner personal data in code, docs, or commits.
- STATE.md is not touched in the build. Its new gotcha text is under "At accept", for the accept-time docs commit.
- No visual-rule variants: nothing visual changes.
- **Gate 1 decision: the script looks up the certificate with `find-identity` without `-v`.** A self-signed certificate is never "valid" to macOS (not trusted), so `-v` would hide it and every build would go ad-hoc. Without `-v`, an expired certificate is also found, and then `codesign` fails and the build stops (`set -eu`). This is on purpose: a silent ad-hoc build would wipe the owner's permissions, and later it would ship an update that does not match the installed app.
- **Gate 1 decision: the owner makes the certificate with `openssl` and `security` on the command line, not with Keychain Access's Certificate Assistant.** The command lines were proven in a scratch keychain; the same `.p12` file is the backup and the restore input; and the validity period is set exactly. Certificate Assistant's flow was not checked.
- **Gate 1 decision: validity is 7300 days (20 years).** This is a pick, not a measured limit. It must be longer than Pauri will ship, because an expired certificate cannot sign, and a new certificate is a new identity: permissions reset and, after the Sparkle ticket, installed copies refuse the update.
- **Gate 1 decision: do not make the certificate before the build finishes.** The builder proves the ad-hoc path first, on a keychain without the certificate. The owner makes the certificate at gate 2 and proves the signed path and the hand check.

## Review Focus

1. **Certificate is in the keychain but expired.** Expected: the build stops with `codesign`'s error and a non-zero exit; it does not fall back to ad-hoc. Not testable without the owner's keychain changing; the scratch-keychain probe above shows the `codesign` error. Covered by the `set -eu` already at the top of the script; no extra code.
2. **A different identity in the keychain has a name that contains `Pauri Self-Signed`, or another identity exists (the owner's keychain has one other, expired, code-signing identity).** Expected: only an exact name match counts. The lookup greps for the name with its quotes, `"Pauri Self-Signed"`, as a fixed string.
3. **The first `codesign` with the login keychain's key.** Expected: macOS may ask once whether `codesign` may use the key; the owner types the login password and clicks Always Allow. Covered in the owner's steps, not in code.
4. **Switching from ad-hoc builds to the first signed build.** Expected: the old grants belong to an old ad-hoc identity, so one reset is needed once; after that, rebuilds keep the grants. Covered in the README text and the hand check.
5. **A contributor without the certificate.** Expected: the build works, signs ad-hoc, prints that it did, and `codesign --verify --strict` passes. Proven by the builder in Task 1 Step 4.

## Owner's one-time steps (at gate 2)

Run each block in Terminal on the Mac that builds Pauri. Nothing here goes in the repo.

**1. Make the certificate.** This writes the private key to a private folder in `$TMPDIR` for a few minutes:

```bash
mkdir -m 700 "$TMPDIR/pauri-cert" && cd "$TMPDIR/pauri-cert" && /usr/bin/openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 7300 -subj "/CN=Pauri Self-Signed" -addext "basicConstraints=critical,CA:false" -addext "keyUsage=critical,digitalSignature" -addext "extendedKeyUsage=critical,codeSigning"
```

**2. Pack it into a password-protected `.p12` file.** It asks for an export password twice. Make a strong one and save it in your password manager now:

```bash
cd "$TMPDIR/pauri-cert" && /usr/bin/openssl pkcs12 -export -inkey key.pem -in cert.pem -name "Pauri Self-Signed" -out Pauri-Self-Signed.p12
```

**3. Import it into the login keychain.** It asks for the `.p12` password. This same line restores the certificate on a new Mac:

```bash
security import "$TMPDIR/pauri-cert/Pauri-Self-Signed.p12" -k ~/Library/Keychains/login.keychain-db -T /usr/bin/codesign
```

**4. Check it.** Expect one line that ends with `"Pauri Self-Signed" (CSSMERR_TP_NOT_TRUSTED)`. "Not trusted" is expected and correct. Do not set it to Always Trust; signing works without it.

```bash
security find-identity -p codesigning | grep -F '"Pauri Self-Signed"'
```

**5. Back it up.** Put `Pauri-Self-Signed.p12` in your password manager as a file attachment, next to its password. A second copy on an offline drive is optional. Do not put it in the repo, an issue, a chat, or any synced folder without its password kept somewhere else. If you lose it, the next build is a new identity: permissions reset, and after the Sparkle ticket, every installed copy refuses updates.

```bash
open "$TMPDIR/pauri-cert"
```

**6. Delete the loose files** after the backup is saved (this removes the unencrypted `key.pem`):

```bash
rm -r "$TMPDIR/pauri-cert"
```

**Restore** (new Mac, or the keychain was reset): get `Pauri-Self-Signed.p12` from the password manager, then run step 3 with its path and step 4.

**Expiry:** the certificate ends 20 years after step 1. After that, the build stops with `Pauri Self-Signed: no identity found`.
