# Markdown Answers and Distinct User Messages Implementation Plan (refs #16)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answers show rendered Markdown (headings, bold, italics, lists, inline code, code blocks, links) instead of raw marks, streaming does not flash half-finished marks, and the user's messages have their own look, picked by the owner from four variants.

**Architecture:** Foundation's `AttributedString(markdown:)` with `.full` syntax already parses every block (it is cmark underneath). A small pure function groups its runs into a flat list of blocks by each run's `presentationIntent`. A new SwiftUI view, `MarkdownView`, draws one native `Text` per block. While an answer streams, a second pure function hides a dangling `**`, `` ` ``, or half link in the last paragraph before parsing. The user's message look comes from the variant the owner picks in `design-directions/issue-16.html`.

**Tech Stack:** Swift 6, SwiftUI, Foundation, Swift Testing. No new dependency, no web view.

**Spec:** issue #16; `docs/spec.md` decisions 14 to 16 (Look). Builds on #5's tool step lines (`design-directions/issue-5.html`, variant A).

## Data flow

No data-flow change: the same `Exchange.answer` and `Exchange.question` strings reach `PanelView`; only how one view draws them changes. Nothing new is read or written, and nothing is fetched.

## What the probe found (2026-11-14, macOS 26, Swift toolchain on this Mac)

A Swift script in the planning session's scratchpad parsed sample answers with
`AttributedString(markdown:options: .init(interpretedSyntax: .full, failurePolicy: .returnPartiallyParsedIfPossible))`
and printed each run's `presentationIntent` and `inlinePresentationIntent`.

- Every block comes through, with a stable `identity` per block: `header 1`, `paragraph`,
  `listItem N < unorderedList` / `orderedList` (nested lists add another `listItem < list` pair),
  `codeBlock 'swift'` (text includes a trailing `\n`, inner blank lines kept), `blockQuote`,
  `thematicBreak` (one run, text `⸻`), and `tableCell N < tableHeaderRow | tableRow N < table`.
- Inline: `stronglyEmphasized` (bold), `emphasized` (italic), `code`, `link` attribute,
  `softBreak` (a single newline becomes a space run), `lineBreak` (two trailing spaces).
- Half-finished input never throws. `"Hello **bol"` stays raw text `Hello **bol`; ``"Hello `cod"``
  stays raw; `"see [the docs](https://exa"` gives raw `see [the docs](` plus a link run. An open
  fence (`"Text\n\n```swift\nlet x"`) already parses as a code block holding `let x`.
- Raw HTML (`<b>`) comes through as literal text runs.

So native text can do everything the ticket asks; no web view is needed (issue constraint).

   `" | "`, the header row bold. No grid.
8. **Images and HTML:** `![alt](url)` shows its alt text and loads nothing (issue constraint: no

### Task 2: Parse Markdown into blocks, and the streaming fix

**Files:**
- Create: `Sources/Pauri/Markdown.swift`
- Test: `Tests/PauriTests/MarkdownTests.swift`

**Interfaces:**
- Produces:

```swift
struct MarkdownBlock: Equatable {
    enum Kind: Equatable {
        case paragraph
        case heading(level: Int)
        /// `marker` is "•" or "N."; nil for a later paragraph in the same item.
        case listItem(depth: Int, marker: String?)
        case code(language: String?)
        case quote
        case rule
        case tableRow(isHeader: Bool)
    }
    var kind: Kind
    var text: AttributedString
}

enum Markdown {
    static func blocks(_ markdown: String) -> [MarkdownBlock]
    static func streamingSafe(_ markdown: String) -> String
}
```

- [ ] **Step 2: Run them to see them fail.** `./scripts/test.sh --filter MarkdownTests`. Expected: build error, `Markdown` not found.

- [ ] **Step 3: Implement `Markdown.blocks` and `Markdown.streamingSafe` in `Sources/Pauri/Markdown.swift`.**

`blocks`: parse with the probe's options (`.full`, `.returnPartiallyParsedIfPossible`); if it throws, return one `.paragraph` of the plain string. Walk `runs`; a run's leaf block is the first component of its `presentationIntent` (`paragraph`, `header`, `codeBlock`, `thematicBreak`, `tableCell`). Consecutive runs with the same leaf identity form one block (`AttributedString(parsed[range])`, appended). Kind from the leaf and its ancestors: `header(level)` -> `.heading`; `codeBlock(hint)` -> `.code` with the trailing `\n` dropped and an empty hint as nil; `thematicBreak` -> `.rule` with empty text; table cells of the same row join into one `.tableRow` with `" | "` between cells, header row from `tableHeaderRow`; a paragraph with a `listItem` ancestor -> `.listItem`, depth = number of list ancestors - 1, marker only on the first leaf of that `listItem` identity (`"•"` under `unorderedList`, `"\(ordinal)."` under `orderedList`); else a `blockQuote` ancestor -> `.quote`; else `.paragraph`.

`streamingSafe`: if the count of lines starting with ```` ``` ```` is odd, return the input unchanged (inside an open fence). Otherwise the tail is the text after the last blank line or fence line. In the tail, in order: an odd count of `**` removes the last `**`; then an odd count of `` ` `` removes the last `` ` ``; then if the last `[` has no `]` after it, remove that `[`; else if `](` follows that `[` with no `)` after it, remove the `[` and cut from `](` to the end.
