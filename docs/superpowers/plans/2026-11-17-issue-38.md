# Zoom the Panel's Content with Cmd+ and Cmd- Implementation Plan (refs #38)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the panel focused, Cmd+ / Cmd= zoom all of the panel's content in one step, Cmd- zooms it out one step, and Cmd+0 goes back to 100%, like a browser. The window's size does not change. Pauri remembers the zoom across hides and relaunches. Dragging the edges still resizes the window (#37).

**Architecture:** Task 1 adds `Sources/Pauri/PanelZoom.swift`, pure rules (range, step, key to command, next zoom, smallest window for a zoom, read and save), with unit tests, and gives `PanelSize.clamped` a `minimum` parameter. Task 2 puts a small `ZoomView` between the glass and the `NSHostingView`: it lays the SwiftUI content out in `frame / zoom` points and AppKit draws it `zoom` times as big (bounds scaling), so text, icons, and spacing all scale and the content reflows, as in a browser. `FloatingPanel.performKeyEquivalent` sends the three keys to `PanelController`, which sets the zoom, the window's smallest size, and saves the zoom. The #37 key-resize code (`PanelSize.step`, `stepped`, `frame(_:resizedTo:within:)`, `direction`) is deleted with its tests, because nothing uses it any more.

**Tech Stack:** Swift 6, AppKit + SwiftUI (macOS 14), Swift Testing. No new dependency.

**Spec:** issue #38 (no design spec; the issue body is the spec). It corrects #37 (`docs/superpowers/plans/2026-11-16-issue-37.md`).

## What exists today (read 2026-11-17)

- `FloatingPanel.performKeyEquivalent` (`Sources/Pauri/PanelController.swift:72-80`) maps Cmd+ / Cmd= / Cmd- through `PanelSize.direction` and steps the window size with `PanelSize.stepped` and `PanelSize.frame(_:resizedTo:within:)`. Nothing else calls those three or `PanelSize.step` (`grep PanelSize\.` in `Sources/`).
- `PanelController.init` puts the `NSHostingView(PanelView)` directly in the `NSVisualEffectView` glass with `autoresizingMask = [.width, .height]`, sets `panel.minSize = PanelSize.minimum` (280 x 280), and opens at `PanelSize.clamped(saved, to: mainScreen)`. `windowWillResize` clamps a drag with `PanelSize.clamped`; `windowDidResize` saves the size.
- Fonts are fixed `.system(size:)` values spread over about 12 files (`grep -n "\.font(" Sources/Pauri/*.swift`), and spacing is fixed points. A font-size zoom would miss the spacing and touch every view.
- No existing shortcut uses `=`, `+`, `-`, or `0` (`keyboardShortcut` is used for Cmd+K, Cmd+N, and the history list keys).
- The settings popover (`PanelView.swift:90`) and the model menu are their own windows.

**Measured in throwaway spikes (2026-11-17, scratch folder, not committed):**
1. `NSHostingView.setBoundsSize(frame / 1.25)` makes AppKit put a 1.25 scale on the host's layer, and SwiftUI lays out in the smaller bounds (`GeometryReader` reported 416 x 544 in a 520 x 680 frame). But SwiftUI does not lay out again until the host's frame changes: `needsLayout`, `layoutSubtreeIfNeeded`, `setFrameSize(sameSize)`, `invalidateIntrinsicContentSize`, and reassigning `rootView` all left it at 520 x 680.
2. Scaling a plain container's bounds and letting the host autoresize inside it went wrong after a window resize (container bounds 480 x 560, host stuck at 416 x 544).
3. A container that sets its own bounds to `frame / zoom` and its one subview's frame to `bounds` in `setFrameSize` and on a zoom change worked: 346.7 x 453.3 at 150%, 400 x 500 after a resize to 600 x 750 at 150%, 600 x 750 after a reset to 100%. This is `ZoomView` in Task 2.
4. Screenshots at 150% on a Retina screen: SF Symbols stay sharp (they are shape layers). **Text is a little soft**, because SwiftUI draws text into a 2x bitmap that the scale then stretches. Forcing the text layers' `contentsScale` to 3 made it sharp, but SwiftUI owns those layers and makes new ones on update, so the plan does not do that.
5. Synthesized mouse clicks did not reach SwiftUI even at 100%, so click mapping under zoom is a hand check, not a test.

## Gate 1 decisions (owner: change any of these before go)

1. **The whole view is scaled, not the font sizes.** `ZoomView` scales the SwiftUI content as one picture, so text, icons, buttons, and spacing all grow together and the text reflows into the narrower room, as in a browser. The cost: at any zoom other than 100%, text is a little softer than at 100% (spike 4). Alternative: multiply every font size by the zoom. Text stays sharp, but spacing and fixed frames do not grow, and about 12 view files change.
2. **Range 80% to 200%, step 10%, Cmd+0 goes to 100%.** The zoom is stored as a whole-number percent, so Cmd+ then Cmd- always comes back to the same value. 13 levels: 80, 90, 100, ..., 200. A press past an end does nothing. Browsers use uneven steps (110, 125, 150, ...); one even step is simpler and the ticket asks for one step size. The range is a guess: 80% of the 11 pt text is about 9 pt; 200% at the default 520 pt width leaves 260 pt of layout room, about the measured smallest `PanelView` (251 pt).
3. **Above 100%, the window's smallest size grows with the zoom: 280 x 280 times the zoom.** So the content never has less room than today's smallest panel (#37 decision 1). At 200% the window must be at least 560 x 560. A drag stops there, and Cmd+ does nothing when the window is too small for the next step: the zoom never resizes the window. Cmd- and Cmd+0 always work. At or below 100% the smallest window stays 280 x 280. This changes #37's drag only at a zoom above 100%. Alternative: let the content get cut off at a small window and a big zoom.
4. **The settings popover, the model menu, and tooltips do not zoom.** They are separate windows, outside the panel's content. The ticket names the header, the messages, and the input.
5. **The zoom is saved on its own key, `panelZoom`, as an Int percent.** Missing or not an Int gives 100; out of range is clamped into 80...200. Reset: `defaults delete io.github.godfreyponce.pauri panelZoom`. The window size stays on `panelSize`.
6. **Cmd+ / Cmd= / Cmd- / Cmd+0 work wherever focus is in the panel**, taken before a text field sees them, as #37 did for the resize keys. Holding the key repeats the step.

### Task 1: The zoom rules

**Files:**
- Create: `Sources/Pauri/PanelZoom.swift`

- Test: `Tests/PauriTests/PanelZoomTests.swift` (new), `Tests/PauriTests/PanelSizeTests.swift` (one new test)

**Interfaces:**
- Produces, on `enum PanelZoom` (all `static`, `import AppKit`):
  - `key: String` = `"panelZoom"`; `default: Int` = `100`; `range: ClosedRange<Int>` = `80...200`; `step: Int` = `10`
  - `enum Command { case zoomIn, zoomOut, reset }`
  - `command(characters: String?, flags: NSEvent.ModifierFlags) -> Command?`: `"="` or `"+"` gives `.zoomIn`, `"-"` gives `.zoomOut`, `"0"` gives `.reset`, else `nil`. Only when `flags.intersection(.deviceIndependentFlagsMask).subtracting([.shift, .capsLock, .numericPad]) == .command` (the rule moved from `PanelSize.direction`).
  - `minimumFrame(at percent: Int) -> CGSize`: `PanelSize.minimum` times `max(percent, 100) / 100` (decision 3).
  - `applied(_ command: Command, to percent: Int, frame: CGSize) -> Int`: `.zoomIn` gives `min(percent + step, range.upperBound)` only when `frame` is at least `minimumFrame(at:)` of that value on both sides, else `percent`; `.zoomOut` gives `max(percent - step, range.lowerBound)`; `.reset` gives `default`.
  - `scale(_ percent: Int) -> CGFloat`: `CGFloat(percent) / 100`.
  - `saved(in defaults: UserDefaults) -> Int`: `defaults.object(forKey: key) as? Int`, clamped into `range`; `default` when missing or not an Int.
  - `save(_ percent: Int, to defaults: UserDefaults)`.
- Produces, on `PanelSize`: `clamped(_ size: CGSize, to screen: CGSize, minimum: CGSize = PanelSize.minimum) -> CGSize`. Same rule as today with the given minimum; existing callers and tests do not change.
