# Release Script and the First GitHub Release (v0.1.0) Implementation Plan (refs #29)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One script on the owner's Mac turns a version such as `0.1.0` into a signed, zipped `Pauri.app` and a signed `appcast.xml` on a new GitHub Release tagged `v0.1.0`, and the README tells people how to install it.

**Architecture:** `scripts/build-app.sh` gets a release mode, `--release X.Y.Z`: it writes the version and `PauriChecksForUpdates = YES` into the bundle's Info.plist before it signs, and it refuses to sign ad-hoc. A new `scripts/release.sh X.Y.Z [--dry-run]` checks everything first, calls the release build, zips with `ditto`, runs Sparkle's `generate_appcast` (which signs the zip with the keychain key and writes `appcast.xml`), then makes the tag and the release in one `gh release create`. `--dry-run` stops before that last step.

**Tech Stack:** POSIX `sh`, `/usr/libexec/PlistBuddy`, `ditto`, `codesign`, `security`, `git`, `gh`, Sparkle 2.10.1's `generate_keys` and `generate_appcast` in `.build/artifacts/sparkle/Sparkle/bin/`.

**Spec:** issue #29 (and its comment from #28). Decisions 1, 4, 9, 10, and 11 of #26.

## Data flow

```text
scripts/release.sh X.Y.Z [--dry-run]  (new)
  |
  | checks: version form, clean tree, git fetch --tags origin, tag vX.Y.Z absent,
  |         X.Y.Z newer than the highest v* tag, HEAD == origin/main (skipped by --dry-run)
  v
scripts/build-app.sh --release X.Y.Z  (changed)
  |  Support/Info.plist --cp--> build/Pauri.app/Contents/Info.plist
  |  PlistBuddy (new): CFBundleShortVersionString = X.Y.Z, CFBundleVersion = X.Y.Z,
  |                    PauriChecksForUpdates = YES
  |  no "Pauri Self-Signed" identity --> exit 1 (new, release mode only)
  v
build/Pauri.app  (signed with Pauri Self-Signed)
  |
  |  generate_keys -p  ==  Support/Info.plist SUPublicEDKey ?  else exit 1   (new)
  |  ditto -c -k --sequesterRsrc --keepParent
  v
build/release/Pauri.zip  (new)
  |
  |  generate_appcast --download-url-prefix https://github.com/godfreyponce/pauri/releases/download/vX.Y.Z/
  |  (reads the private key from the login keychain, account ed25519)
  v
build/release/appcast.xml  (new)
  |
  |  --dry-run: stop here, print both paths
  v
gh release create vX.Y.Z --target <HEAD sha>  --> GitHub: tag vX.Y.Z + Release with
                                                  Pauri.zip and appcast.xml as assets
git fetch origin tag vX.Y.Z  --> local tag

Installed app --> https://github.com/godfreyponce/pauri/releases/latest/download/appcast.xml
```

### Gate 1 decisions

- **`CFBundleVersion` = the version string (`0.1.0`), not a separate counter.** Sparkle compares dotted versions part by part, and Apple allows up to three dot-separated integers. The script refuses a version that is not newer than the highest `v*` tag (`sort -V`), so `CFBundleVersion` goes up with every release with no counter to keep. `Support/Info.plist` changes `CFBundleVersion` from `1` to `0.1.0`: with `1`, a dev build would look newer than every `0.x` release (1 > 0), and the README's `PauriTestFeedURL` test hook would never show the button. The other choice is an integer build number, such as the commit count; it can repeat when two releases come from one commit.
- **The script needs the certificate, and the certificate is not in the keychain today.** Before go, restore it from `Pauri-Self-Signed.p12` with steps 3 and 4 of "Owner's one-time steps" in `docs/superpowers/plans/2026-11-16-issue-27.md` (or make it again; a new one is a new identity, and macOS asks for the four permissions again). If it is still missing at build time, the build session proves only the "certificate missing" stop, and the owner's dry run at gate 2 proves the rest.
- **A `--dry-run` flag.** The ticket does not ask for it, but it is the only way the build session (and the owner, before the real run) can run the whole script without publishing. It skips one check (HEAD == origin/main, which a ticket branch never passes) and stops before `gh release create`.
- **One extra stop: HEAD must equal `origin/main`.** `gh release create --target <sha>` needs the commit on GitHub, and a release from a ticket branch or an unpushed commit would ship code that is not on main. So the owner runs the real release from the main folder after the accept push.
- **The tag is made by `gh release create`, not by `git tag` + `git push`.** One call makes the tag and the release, so a failed upload cannot leave a tag with no release (a rerun would then stop at "tag exists"). The script then fetches the tag so it is local too.
- **The asset is named `Pauri.zip` in every release**, so the README can link `https://github.com/godfreyponce/pauri/releases/latest/download/Pauri.zip`. The versioned folder in the download URL keeps each release's file apart. #30's cask can use `releases/download/v#{version}/Pauri.zip`.
- **The appcast holds only the new release.** Installed copies read the feed of the latest release, so older items add nothing.
- **The update key is checked by comparing `generate_keys -p` with `SUPublicEDKey`**, not only by its presence: a different key in the keychain would ship an update every installed copy refuses. The check runs after the build, because the tool exists only after `swift build` has fetched Sparkle; it still runs before anything is published.

## Review Focus

1. **A leftover `build/release/` from an earlier run.** `generate_appcast` would reuse its `appcast.xml` and add the old zip to `old_updates/`. Expected: the script deletes `build/release/` first. Task 2 Step 5 runs the dry run twice and checks the second appcast has one item.
2. **A release from a ticket branch or an unpushed commit.** Expected: stop before the build with a message to release from main after the push. Task 2 Step 4 checks it by reading only, because running it means taking the publish path.
3. **A version lower than an existing release (`0.0.9` after `0.1.0`).** Sparkle would never offer it. Expected: stop, naming the highest tag. Task 2 Step 4.
4. **A downloaded copy run from `~/Downloads`.** macOS runs a quarantined app from a random read-only path (App Translocation), and Sparkle cannot replace it. Expected: the README's steps move `Pauri.app` to `/Applications` before the first open. Task 3.
5. **The keychain asks to allow `generate_keys` or `generate_appcast`.** These binaries live under the folder's `.build/`, so a new folder asks again. Expected: the owner clicks Always Allow; a refusal makes the tool fail and the script stop before publishing. Task 2 Step 5 and the owner's steps say so.

### Task 2: `scripts/release.sh`

**Files:**
- Create: `scripts/release.sh` (executable, `#!/bin/sh`, `set -eu`, `cd "$(dirname "$0")/.."`)

**Interfaces:**
- Consumes: `./scripts/build-app.sh --release X.Y.Z` (Task 1).
- Produces: `scripts/release.sh X.Y.Z [--dry-run]`. Writes `build/release/Pauri.zip` and `build/release/appcast.xml`. Without `--dry-run`, makes tag `vX.Y.Z` and its GitHub Release.

- [ ] **Step 1: Write the script.** In this order; each stop prints `release: <message>` to stderr and exits 1:
  1. Usage: first argument must match `^[0-9]+\.[0-9]+\.[0-9]+$`; second is empty or `--dry-run`. Else `release: usage: scripts/release.sh X.Y.Z [--dry-run]`.
  2. Clean tree: `git status --porcelain` is empty. Else `The working tree has changes. Commit or remove them first.`
  3. `git fetch -q --tags origin`.
  4. Tag absent: `git rev-parse -q --verify "refs/tags/vX.Y.Z"` fails. Else `Tag vX.Y.Z already exists.`
  5. Newer: the highest of `git tag -l 'v[0-9]*'` (strip `v`, `sort -V`) is lower than X.Y.Z, or there is none. Else `X.Y.Z is not newer than v<highest>. Sparkle would not offer it.`
  6. Unless `--dry-run`: `git fetch -q origin main`, then `git rev-parse HEAD` equals `git rev-parse origin/main`. Else `HEAD is not origin/main. Release from main after you push.`
  7. `./scripts/build-app.sh --release X.Y.Z` (its own stop covers the missing certificate).
  8. Update key: `.build/artifacts/sparkle/Sparkle/bin/generate_keys -p` succeeds, and its output equals `PlistBuddy -c 'Print :SUPublicEDKey' Support/Info.plist`. Capture the output in a variable; never echo it. Missing: `No Sparkle update key in the keychain. Restore it: docs/superpowers/plans/2026-11-16-issue-28.md ("Owner's one-time steps").` Different: `The keychain's update key does not match SUPublicEDKey in Support/Info.plist. Installed copies would refuse this update.`
  9. `rm -rf build/release && mkdir -p build/release`, then `ditto -c -k --sequesterRsrc --keepParent build/Pauri.app build/release/Pauri.zip`.
  10. `generate_appcast --download-url-prefix "https://github.com/godfreyponce/pauri/releases/download/vX.Y.Z/" build/release`.
  11. `--dry-run`: print `Dry run: nothing published.` and the two file paths, exit 0.
  12. `gh release create vX.Y.Z build/release/Pauri.zip build/release/appcast.xml --target "$(git rev-parse HEAD)" --title vX.Y.Z --notes vX.Y.Z`, then `git fetch -q origin tag vX.Y.Z`, then print `Released vX.Y.Z: https://github.com/godfreyponce/pauri/releases/tag/vX.Y.Z`.
