# Starry Orb Send Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The panel gets a send button: a purple sphere with small stars, a soft glow, and a white up arrow, as in `docs/reference/send-orb.png`. Sending plays a small animation, and Reduce Motion turns that animation down.

**Architecture:** First, a single HTML page shows four send animations side by side, all on the same drawn orb. The owner picks one. Then `SendOrb.swift` draws the orb in SwiftUI (gradients, a fixed star list, a shadow, the SF Symbol `arrow.up`) and plays the chosen animation each time a counter goes up. `PanelView` puts the orb after the text field. Enter and a click both go through one `submit()` that calls `Chat.send` and bumps the counter only when the send is accepted.

**Tech Stack:** Swift 6.2 (Command Line Tools), SwiftPM, SwiftUI (macOS 14: `keyframeAnimator`, `phaseAnimator`, `accessibilityReduceMotion`), one static HTML file with inline CSS and JS. No third-party dependency, no image asset.

**Spec:** `docs/spec.md` decision 15; issue #10. Reference image `docs/reference/send-orb.png`.

## Data flow

No data-flow change: the orb calls the same `Chat.send` that the Enter key already calls, and no file, script, or service starts or stops reading or writing anything. The HTML page is a design record that nothing reads.

## Gate 1 decisions (owner: change any of these before go)

1. **The 4-variant visual pass happens (unlike #1 and #12).** The spec's Fog line says the design pass covers "visual polish past the send button and glass", so the send button is in scope for the owner's visual rule. The page goes in `design-directions/issue-10.html` (AGENTS.md `# Visual rule`). The build stops after Task 1 so the owner can pick, and Task 2 waits for that pick.
2. **References for the page:** (a) `docs/reference/send-orb.png` for the orb itself; (b) `docs/reference/chatgpt-window.png` for where the button sits (round, at the right end of the input row); (c) Pauri's current panel (the system dark window, no glass yet). Swap in a link or screenshot of your own if these miss the feel.
3. **The four variants share one static look and differ in the send animation.** The reference fixes the look, so only the animation is open:
   - **A. Press and ring.** The orb shrinks a little, springs back, and one glow ring grows out from it and fades.
   - **B. Arrow launch.** The arrow flies up out of the orb and fades. A new arrow rises in from below, and the stars streak upward once.
   - **C. Star spin.** The star layer turns a quarter turn around the center while the glow brightens and then settles. The orb does not move.
   - **D. Breathing while answering.** Sending starts a slow glow pulse that runs until the answer finishes (`Chat.isAnswering`), and then the orb goes still. This is the only variant tied to how long the answer takes, not to the click.
4. **Size 32 pt.** In `chatgpt-window.png` the send circle is about 64 px across in a window about 1045 px wide. That is 2x of Pauri's 520 pt panel, so 32 pt.
5. **Colors measured from `send-orb.png`:** body deep indigo `#121440`, rim upper right violet `#24215C`, the lower crescent from blue `#4152A6` on the left to violet `#463C92` on the right, arrow white `#FFFFFF`. The page keeps these as named constants at the top, and Task 2 copies the same values.
6. **The orb is dimmed (opacity 0.4, a guess the page lets you judge) and disabled when the draft is blank or an answer is streaming.** `Chat.send` already refuses both cases, so a bright orb that does nothing would mislead.
7. **No `InputBar.swift` yet.** The issue guesses that file, but the input row is one `HStack` with two views. Splitting it out now is structure for #4, #7, and #11, which they can add when they need it.
8. **Reduce Motion:** nothing moves. The glow brightens once and fades back (opacity only), so the user still sees that the send was accepted. Variant D shows a steady brighter glow while answering, with no pulse.

- [ ] **Step 1: Write the page**

One self-contained file: inline CSS and JS, no network, no build step. Dark page background `#0D0D0D` (the reference's background).

At the top of the `<script>`, define the shared data once:
- `ORB` — size `32` (pt, drawn at 1 CSS px = 1 pt and also at 3x for detail), the colors from gate 1 decision 5, glow color and radius.
- `STARS` — 8 fixed points `{x, y, r, opacity}` with x and y in 0...1 of the orb's box, inside the upper two thirds and off the arrow. `r` 0.5–0.9 pt, opacity 0.35–0.8. No random numbers at render time.
- `DRAFT` — `"what does max(d, key=d.get) return?"`, shown in a fake one-line text field next to each orb.
- `DURATIONS` — one entry per variant in ms. Starting values are guesses (A 350, B 450, C 500, D pulse period 1600). The owner judges them on the page.

Layout: four columns labeled A to D with the one-line description from gate 1 decision 3. Each column holds a fake input row (field plus orb at 1x), the same orb at 3x, and `send-orb.png` at its natural size beside the 3x orb. Each column has its own **Send** control that plays that variant. For D, it also has a **Finish answer** control that ends the pulse. A page-level checkbox, **Reduce Motion**, switches every variant to its reduced form (gate 1 decision 8). The page also honors `@media (prefers-reduced-motion: reduce)` at load. One more page-level checkbox, **Disabled**, shows the dimmed state from gate 1 decision 6.

Draw the orb with CSS only: a `radial-gradient` body, a second gradient for the lower crescent, absolutely placed star dots from `STARS`, a `box-shadow` glow, and a white up-arrow drawn in SVG.

- [ ] **Step 1: Write `SendOrb` in `Sources/Pauri/SendOrb.swift`**

- Draw it with a `ZStack` in a 32 x 32 frame: `Circle` filled with a `RadialGradient` (body and rim colors), a second `Circle` filled with a `LinearGradient` (the crescent colors) and masked to the lower part, the stars as small `Circle`s placed with `.position` from a `private static let stars` array copied from `STARS`, then `Image(systemName: "arrow.up")` with `.font(.system(size: 14, weight: .bold))` and `.foregroundStyle(.white)`. Use `.shadow` with the glow color for the glow.
- Put it in a `Button(action:)` with `.buttonStyle(.plain)`, `.focusable(false)`, `.disabled(!isEnabled)`, `.opacity(isEnabled ? 1 : 0.4)`, `.help("Send")`, and `.accessibilityLabel("Send")`.
- Animation: for A, B, or C use `.keyframeAnimator(initialValue:trigger: sends)` with the page's durations. For D use `.phaseAnimator` while `isAnswering`. Read `@Environment(\.accessibilityReduceMotion)`. When it is on, use the opacity-only glow form from gate 1 decision 8, and change no scale, offset, or rotation.

- [ ] **Step 2: Route Enter and the click through `submit()` in `PanelView.swift`**

Add `@State private var sends = 0` and:

```swift
private func submit() {
    if chat.send(draft) {
        draft = ""
        sends += 1
    }
}
```

Replace the `TextField` block with an `HStack` holding the `TextField` (`.onSubmit(submit)`, the rest unchanged) and `SendOrb(sends: sends, isEnabled: !draft.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty && !chat.isAnswering, isAnswering: chat.isAnswering, action: submit)`.
