# Header Icons Get Hover Labels Implementation Plan (refs #35)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pointing at the panel header's search, new chat, and settings icons shows a label, drawn by #34's `HoverLabel`, the same way the update icon's label is drawn. The search icon's label names its shortcut, ⌘K.

**Architecture:** Three one-line swaps in `Sources/Pauri/PanelView.swift`, lines 80, 84, and 89: each `.help("...")` on a header button becomes `.modifier(HoverLabel(text: "..."))`. `HoverLabel` (same file, line 321) does not change. `.help` never shows on this panel, because AppKit draws tooltips only for the active app and the nonactivating panel never activates Pauri.

**Tech Stack:** Swift 6, SwiftPM, SwiftUI.

**Spec:** issue #35 (no design spec).

## Data flow

No data-flow change: only how three existing labels are drawn changes. No file, command, or service starts or stops reading or writing anything.

## Global Constraints

- Reuse #34's `HoverLabel`. Do not add a second tooltip mechanism, and do not change `HoverLabel` (issue #35, Constraints).
- The words stay as they are today. Search: `"Past chats (⌘K)"`, which names the shortcut and so meets the second Done-when item. New chat: `"New chat"`. Settings: `"Settings"`. (Gate 1 decision: the new chat label does not add ⌘N. The ticket asks for a shortcut only on search.)
- No visual-rule variants. The look is already fixed: the ticket requires #34's `HoverLabel`, the owner picked that look at #34, and the words already exist. (Gate 1 decision.)
- Only the header's three `.help` calls change. The other `.help` calls in the app (screenshot, dictate, send, model picker, history rows, chips) are out of scope, even though they have the same problem. If the builder wants them fixed, it files a new issue and does not touch them here.
- Hover has no automated test (issue #35, Constraints; AGENTS.md `# Verification scope`). No new test is written. The owner checks hover by hand on the built app.

## Review Focus

1. **Modifier order on the new chat button.** `.modifier(HoverLabel(...))` goes after `.disabled(!chat.canStartNewChat)`, so the label still shows while an answer streams and the button is disabled. `HoverLabel` outside `.disabled` is the pattern #34 already uses on the up-arrow (line 68 then 70) and on `UpdateStatusIcon`'s `.off` case. The hand check covers it: hover the new chat icon during an answer.
2. **The shortcuts still work.** ⌘K and ⌘N must still fire. `.keyboardShortcut` stays on each button, and `HoverLabel` only adds `onHover` and an overlay that ignores clicks (`.allowsHitTesting(false)`). The hand check presses both.
3. **Settings label and its popover.** The settings label shows under the gear. After a click the popover opens below the gear, and the label may show under the popover's edge or stay up until the pointer moves. The owner checks this by hand. If it looks wrong, that is a gate 2 note, not something to fix with new code in this ticket.
4. **The label stays inside the panel.** `HoverLabel` sets the label's trailing edge on the icon's trailing edge, so labels grow to the left. The settings icon is the rightmost one, so its label cannot pass the panel's right edge. The owner checks this by hand at the narrowest panel width (#37's resizable panel).

- [ ] **Step 1: Swap the three `.help` lines**

```swift
// line 80, search button
.help("Past chats (⌘K)")   -->   .modifier(HoverLabel(text: "Past chats (⌘K)"))
// line 84, new chat button

On the search and settings buttons, the `HoverLabel` line takes the `.help` line's place. No other line in the file changes.
