# Hotkey Opens a Floating Panel Implementation Plan (refs #1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A global hotkey shows a small SwiftUI panel over every app, fullscreen ones too, with its input box focused; the hotkey again, or Esc, hides it. One documented command builds `Pauri.app` from a clean clone.

**Architecture:** A SwiftPM package with one executable target, `Pauri`. A SwiftUI `App` hands off to an `NSApplicationDelegate`, which owns a `PanelController` (an `NSPanel` hosting a SwiftUI view) and a `HotKey` (Carbon `RegisterEventHotKey`). A shell script wraps the release binary and a checked-in `Info.plist` into `build/Pauri.app`.

**Tech Stack:** Swift 6.2 (Command Line Tools, no Xcode on the owner's Mac), SwiftPM, SwiftUI, AppKit, Carbon HIToolbox, Swift Testing. No third-party dependency.

**Spec:** `docs/spec.md` decisions 2, 3, 4; issue #1.

## Gate 1 decisions (owner: change any of these before go)

1. **Default hotkey: Cmd+Shift+Space.** The ticket bans Option+Space. On this Mac, `com.apple.symbolichotkeys` has Ctrl+Option+Space enabled (next input source) and has no entry for Cmd+Shift+Space. Ctrl+Space and Cmd+Space are system defaults too (disabled here, but on for most users). #12 makes it configurable.
2. **No 4-variant visual pass in this ticket.** The panel is a plain placeholder: one text field at the bottom of an opaque window. The look belongs to #9 (glass), #10 (orb), and the spec's Fog item "a design-directions pass once the bones work". The visual rule applies there.
3. **No quit UI.** The app is a menu-bar-less agent (`LSUIElement`), so it has no Dock icon and no menu. Quit with `pkill -x Pauri`. No ticket covers a quit item yet; if you want one, it is a new issue, not this one.
4. **SwiftPM plus a script, not an Xcode project.** The owner's Mac has only Command Line Tools (`xcodebuild` fails: "requires Xcode"), so an `.xcodeproj` cannot be built here.
5. **Swift Testing needs extra flags under Command Line Tools.** Probed 2026-11-13: plain `swift test` fails with `no such module 'Testing'`; with `-F`/`-rpath` to `/Library/Developer/CommandLineTools/Library/Developer/Frameworks` it runs. `scripts/test.sh` adds those flags only when `xcode-select -p` is the CLT folder.
6. **Bundle id `io.github.godfreyponce.pauri`.** It follows the public repo URL. Later tickets key permissions (#6, #7) and saved settings (#9, #12) to it, so changing it later resets those.
7. **Panel size 520 x 680 points.** Measured from `docs/reference/floating-over-apps.png`: the ChatGPT window is about 1045 x 1360 pixels in a 2x screenshot.
8. **Minimum macOS 14.** Needed for `MainActor.assumeIsolated`. The owner runs macOS 26.

## Global Constraints

- Native Swift, SwiftUI inside an `NSPanel`. No Tauri, no web view.
- No Codex calls. The input box only takes text; Return does nothing.
- The hotkey is a fixed default. No settings UI (that is #12).
- No new dependency.
- Public repo: no env values, credentials, or owner personal data in commits.
- Commit form, from AGENTS.md `# Commit format`: `type(scope): summary (refs #1)`. Trailers: the harness default `Co-Authored-By` line, nothing else.
- STATE.md is not touched in this build. Its `## Run / verify` gets the new commands in the accept-time docs commit.

## Review Focus

Conditions the tests do not reach. Each is a manual check in the final task.

1. Hotkey while the panel is visible but another app has focus (the user clicked away): the panel comes back and takes focus; it does not hide. Only a press while the panel is the key window hides it.
2. Esc with text typed: the panel hides and the draft text is still there on the next show.
3. Typing in the panel: the app behind stays the active app (its menu bar stays), and keystrokes go to the panel, not to it.
4. The hotkey is already taken by another app: `RegisterEventHotKey` fails, Pauri logs the `OSStatus` with `NSLog`, and keeps running.
5. Switching Spaces or into a fullscreen app while the panel is shown: the panel stays on top in the new Space.

### Task 2: Floating panel, global hotkey, app bundle

**Files:**
- Modify: `Sources/Pauri/HotKey.swift` (add `HotKey`)
- Create: `Sources/Pauri/PanelController.swift`
- Create: `Sources/Pauri/PanelView.swift`
- Modify: `Sources/Pauri/PauriApp.swift` (add `AppDelegate`)
- Create: `Support/Info.plist`
- Create: `scripts/build-app.sh` (mode 755)

**Interfaces:**
- Consumes: `Shortcut.default` (Task 1).
- Produces: `@MainActor final class HotKey { init(shortcut: Shortcut, action: @escaping @MainActor () -> Void) }`.
- Produces: `@MainActor final class PanelController { init(); func toggle(); func show(); func hide() }`.
- Produces: `scripts/build-app.sh`, which prints `build/Pauri.app` on success.

No automated test in this task: what it delivers (a system-wide hotkey, window level over fullscreen Spaces, key focus) needs a window server and real key presses. The final task checks it by hand. A test that only asserts panel flags would pin the implementation, not the behavior.

- [ ] **Step 1: `HotKey`**

`InstallEventHandler` on `GetApplicationEventTarget()` for `kEventClassKeyboard` / `kEventHotKeyPressed`, then `RegisterEventHotKey(shortcut.keyCode, shortcut.modifiers, EventHotKeyID(signature: "PAUR" as a FourCharCode, id: 1), GetApplicationEventTarget(), 0, &ref)`. Pass `self` as `userData` with `Unmanaged.passUnretained`. The C callback calls `action` inside `MainActor.assumeIsolated` (Carbon delivers application-target events on the main thread). If either call returns non-`noErr`, `NSLog("Pauri: hotkey registration failed, OSStatus %d", status)` and return; the app keeps running. No `deinit`: one `HotKey` lives for the app's lifetime.

- [ ] **Step 2: `PanelController` and its panel**

In `PanelController.swift`, a private `NSPanel` subclass:
- `canBecomeKey` returns `true`.
- `cancelOperation(_:)` calls `orderOut(nil)` (Esc). If the gate check shows Esc does not reach the panel from the text field, move it to `.onExitCommand` in `PanelView` instead.

`PanelController.init()` builds it with:
- `contentRect` 520 x 680 (gate 1 decision 7), `styleMask: [.nonactivatingPanel, .titled, .fullSizeContentView]`, `titleVisibility = .hidden`, `titlebarAppearsTransparent = true`, `isMovableByWindowBackground = true`.
- `level = .floating`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`, `hidesOnDeactivate = false`, `isReleasedWhenClosed = false`. If the panel does not appear over a fullscreen app at the gate check, raise `level` to `.statusBar` and say so in the gate 2 report.
- `contentView = NSHostingView(rootView: PanelView())`, then `center()` once.

Methods: `show()` = `makeKeyAndOrderFront(nil)`. `hide()` = `orderOut(nil)`. `toggle()` = `isKeyWindow ? hide() : show()` (Review Focus 1). Do not call `NSApp.activate`: the app behind must stay active (Review Focus 3).

- [ ] **Step 3: `PanelView`**

`struct PanelView: View`: `@State private var draft = ""`, `@FocusState private var focused: Bool`. A `VStack` with a `Spacer()` above a `TextField("Ask Pauri", text: $draft)`, `.textFieldStyle(.roundedBorder)`, `.focused($focused)`, padded. `.onReceive(NotificationCenter.default.publisher(for: NSWindow.didBecomeKeyNotification)) { _ in focused = true }`: the panel becomes key on every show, so this focuses the field every time. It is the app's only window that can become key.

- [ ] **Step 4: `AppDelegate`**

In `PauriApp.swift`: `@MainActor final class AppDelegate: NSObject, NSApplicationDelegate` holding `panel: PanelController?` and `hotKey: HotKey?`. `applicationDidFinishLaunching` creates the controller, then `HotKey(shortcut: .default) { [weak self] in self?.panel?.toggle() }`. Add `@NSApplicationDelegateAdaptor(AppDelegate.self) var appDelegate` to `PauriApp`.

- [ ] **Step 5: `Support/Info.plist` and `scripts/build-app.sh`**

`Info.plist` keys: `CFBundleExecutable` `Pauri`, `CFBundleIdentifier` `io.github.godfreyponce.pauri` (gate 1 decision 6), `CFBundleName` `Pauri`, `CFBundlePackageType` `APPL`, `CFBundleShortVersionString` `0.1.0`, `CFBundleVersion` `1`, `LSMinimumSystemVersion` `14.0`, `LSUIElement` `true`.

`scripts/build-app.sh`: `#!/bin/sh`, `set -eu`, `cd` to the repo root, `swift build -c release --product Pauri`, take the binary from `$(swift build -c release --show-bin-path)/Pauri`, `rm -rf build/Pauri.app`, create `build/Pauri.app/Contents/MacOS`, copy the binary to `Contents/MacOS/Pauri` and `Support/Info.plist` to `Contents/Info.plist`, print `build/Pauri.app`.

- [ ] **Step 6: Build and launch**

Run: `./scripts/build-app.sh && open build/Pauri.app && sleep 2 && pgrep -x Pauri && log show --last 1m --predicate 'process == "Pauri"' | grep -c "hotkey registration failed"`
Expected: `build/Pauri.app`, a PID, and `0`. No Dock icon appears. Leave it running for the owner's gate check, or quit with `pkill -x Pauri`.

