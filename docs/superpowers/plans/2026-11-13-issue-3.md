# Follow-ups, Reopen Last Chat, Cmd+N Implementation Plan (refs #3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The panel shows the whole chat, every turn goes to the same Codex thread, the last chat comes back after a relaunch, and Cmd+N starts a blank one.

**Architecture:** Codex already keeps each thread on disk (`~/.codex/sessions`). Pauri stores only the thread id, in `UserDefaults` under `lastThreadID`. At start, `CodexClient` resumes that thread with `thread/resume`, which returns the old turns; `Chat` shows them above any new ones. Cmd+N forgets the id, and the next question starts a new thread on the same warm process.

**Tech Stack:** Swift 6, SwiftUI, AppKit, Foundation, Swift Testing. No new dependency.

**Spec:** `docs/spec.md` decision 11; issue #3. Builds on #2's plan, `docs/superpowers/plans/2026-11-13-issue-2.md`.

## What the probe found (2026-11-13, codex-cli 0.167.2, this Mac)

A Python probe in the planning session's scratchpad drove the real server.

- Follow-ups already work on one thread: "what is 2+2" answered `4`, then "times 3" answered `12`.
- `thread/resume` with `{threadId, cwd, sandbox, approvalPolicy}` on a **new** process returned in
  180 ms. `result.thread.turns` held both turns, `itemsView: "full"`. Each turn's `items` had
  `{"type":"userMessage","content":[{"type":"text","text":"what is 2+2","text_elements":[]}]}`
  and `{"type":"agentMessage","text":"4", ...}`. Other item types exist (`reasoning`,
  `functionCallOutput`, `plan`, ...). A follow-up on the resumed thread ("and minus 2?") answered `10`.
- A resume of an unknown id fails with `{"code":-32600,"message":"no rollout found for thread id ..."}`.
- A thread with **no turns** cannot be resumed: same "no rollout found" error. Codex writes the
  thread to disk only at its first turn.
- `thread/start` on a warm process: 16, 5, 6 ms.
- `ThreadResumeParams` says full-turn hydration is "deprecated for paginated threads" in favor of
  `thread/turns/list`. It works today; a later codex version may need the paged call.

## Gate 1 decisions (owner: change any of these before go)

1. **Codex keeps the chat; Pauri keeps only its id.** The id lives in `UserDefaults` (`lastThreadID`), next to #12's `hotKey`. At start Pauri resumes that thread and reads the old turns from the reply. The other choice is a transcript file that Pauri writes itself: a second copy that can disagree with what Codex remembers.
2. **Not a visual ticket.** The transcript is plain, selectable text: each question in bold, its answer under it. The new-chat button is an SF Symbol (`square.and.pencil`) left of the gear. The look is #9 and #10, where the visual rule applies.
3. **The id is saved only after a question's `turn/start` succeeds, and Cmd+N starts no thread.** A thread with no turns cannot be resumed (probe), so saving an empty one would only cost a failed resume at the next launch. The next question after Cmd+N starts the thread, about 5 ms on the warm process.
4. **Cmd+N is off while an answer streams and while the start at launch runs.** It does not stop the answer. Stopping a turn (`turn/interrupt`) is new protocol work that no ticket asks for yet.
5. **A saved chat that cannot be resumed opens a blank chat, with no notice.** This covers a deleted `~/.codex/sessions` file and a codex update that drops the old thread. Any error reply to `thread/resume` counts; a dead process still shows "Codex stopped".
6. **The transcript stays scrolled to the bottom** (`.defaultScrollAnchor(.bottom)`), so a new answer is in view as it streams. #2 did not scroll because one answer fit.

## Global Constraints

- Keep using the one warm `codex app-server` process from #2. Cmd+N and resume never spawn a second one.
- No history list (issue #3 constraint).
- Pauri never opens anything under `~/.codex` and stores nothing from Codex except the thread id.
- `thread/resume` passes the same overrides as `thread/start`: `"cwd": <home>`, `"sandbox": "read-only"`, `"approvalPolicy": "never"`.
- `UserDefaults` key: `lastThreadID` (a `String`). Bundle id: `io.github.godfreyponce.pauri`.
- No new dependency.
- Public repo: no env values, credentials, emails, or owner personal data in commits or test fixtures.
- Commit form, from AGENTS.md `# Commit format`: `type(scope): summary (refs #3)`. Trailers: the harness default `Co-Authored-By` line, nothing else.
- Multi-task plan: one commit per task on branch `issue-3`. STATE.md is not touched in this build.

## Review Focus

1. **Codex dies mid-chat, then a follow-up.** `pkill -f "codex app-server"`, then ask "times 3": the new process resumes the saved thread, so the answer still uses the earlier turns. `launch()` resumes the stored id every time it runs, not only at app launch. Manual check 5.
2. **The saved thread is gone** (bogus or deleted id): the panel opens blank with no notice, and the first question answers. Manual check 6.
3. **Cmd+N, then quit before asking anything:** the relaunch is blank, because Cmd+N removed the id and no turn saved a new one. Live test in Task 2 (`forgetThread()` then a new client restores nothing) and manual check 4.
4. **Return during the start at launch, with a saved chat:** the old turns appear above the new question, not after it and not in place of it. `Chat.warmUp` inserts the restored turns at index 0, and `send` writes deltas to the last exchange. Manual check 3.
5. **Cmd+N during an answer or during the start at launch:** nothing happens (button disabled). Without the guard, the start at launch would set the resumed thread after Cmd+N forgot it, and a streaming answer would land in the blank chat. Manual check 4.

### Task 2: CodexClient resumes the saved thread and forgets it on request

**Files:**
- Modify: `Sources/Pauri/CodexClient.swift`
- Test: `Tests/PauriTests/CodexClientLiveTests.swift`

**Interfaces:**
- Consumes: `Exchange`, `ThreadResumeResult` (Task 1); the existing `send`, `decode`, `ThreadStartResult`.
- Produces:
  - `init(defaults: UserDefaults = .standard)`, stored as `private let defaults`. Key: `private static let threadKey = "lastThreadID"`.
  - `private(set) var restoredExchanges: [Exchange] = []`: the turns of the thread the last `launch()` resumed; `[]` when it started a new thread.
  - `func forgetThread()`: sets `threadID = nil` and removes `lastThreadID`. Synchronous. The next `ask` starts a new thread.
  - `start()` and `ask(_:)` keep their signatures.

Behavior to build:
- `launch()`, after the login check: if `defaults.string(forKey: threadKey)` is set, send `thread/resume` with `"threadId"` plus the three overrides from Global Constraints. On success set `threadID` and `restoredExchanges` from the reply. On `CodexProblem.failed` (any error reply), remove the key and fall through to a new thread. Any other error is thrown. With no key, or after the fallback: `threadID = try await startThread()` and `restoredExchanges = []`.
- `private func startThread() async throws -> String`: the existing `thread/start` call, moved out of `launch()`.
- `ask(_:)`: after `try await start()`, add `if threadID == nil { threadID = try await startThread() }` before the existing `guard let threadID else { throw CodexProblem.stopped }`, which stays to unwrap. After the `turn/start` reply arrives, `defaults.set(threadID, forKey: Self.threadKey)`.
- `reset(failing:)` keeps clearing `threadID` but does **not** touch `defaults`, so the next start resumes the same chat (Review Focus 1).

- [ ] **Step 1: Write the live test** in `CodexClientLiveTests.swift`. Add a helper, and pass fresh defaults to the existing `liveTwoQuestionsOneProcess` too (`CodexClient(defaults: freshDefaults("pauri-live-two-questions"))`), so the live tests never resume a thread left by an earlier run. Each test uses its own suite name: Swift Testing runs tests in parallel, and a shared suite would be wiped under the other test.

```swift
@MainActor private func freshDefaults(_ name: String) -> UserDefaults {
    let defaults = UserDefaults(suiteName: name)!
    defaults.removePersistentDomain(forName: name)
    return defaults
}

@MainActor private func answer(_ client: CodexClient, _ question: String) async throws -> String {
    var answer = ""
    for try await delta in client.ask(question) { answer += delta }
    return answer
}

@Test(.enabled(if: ProcessInfo.processInfo.environment["PAURI_LIVE"] == "1"))
@MainActor func liveFollowUpSurvivesRelaunch() async throws {
    let defaults = freshDefaults("pauri-live-relaunch")
    let first = CodexClient(defaults: defaults)
    try await first.start()
    #expect(first.restoredExchanges.isEmpty)
    _ = try await answer(first, "what is 2+2")
    #expect(try await answer(first, "times 3").contains("12"))

    let relaunched = CodexClient(defaults: defaults)
    try await relaunched.start()
    #expect(relaunched.restoredExchanges.map(\.question) == ["what is 2+2", "times 3"])

    relaunched.forgetThread()
    let afterNewChat = CodexClient(defaults: defaults)
    try await afterNewChat.start()
    #expect(afterNewChat.restoredExchanges.isEmpty)
}
```
