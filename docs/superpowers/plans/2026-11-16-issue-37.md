# Resize Pauri's Panel Implementation Plan (refs #37)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user can resize the panel by dragging its edges and corners, or with Cmd+ / Cmd= (bigger) and Cmd- (smaller) while it has focus, and Pauri remembers the size across hides and relaunches.

**Architecture:** Task 1 adds `Sources/Pauri/PanelSize.swift`, a set of pure rules (default, minimum, step, clamp to the screen, keep the panel on the screen, read and save the size, map a key press to a step), with unit tests. Task 2 wires them in: `.resizable` on the panel, a `performKeyEquivalent` override on `FloatingPanel` for the three keys, and `PanelController` as the window delegate that caps a drag at the screen size and saves the size after every resize. Then the README line, the hand check, and the full check.

**Tech Stack:** Swift 6, AppKit + SwiftUI (macOS 14), Swift Testing. No new dependency.

**Spec:** issue #37 (no design spec; the issue body is the spec).

## Data flow

```text
PanelController.init (changed)
    |  PanelSize.saved(in: .standard)  (new read)
    v
UserDefaults key "panelSize" (new)  {"width": Double, "height": Double}
    ^
    |  PanelSize.save(_:to:)  (new write)
    |
PanelController.windowDidResize (new) <-- FloatingPanel frame changes
                                              ^              ^
                       edge/corner drag (new) |              | FloatingPanel.performKeyEquivalent (new)
       capped by windowWillResize (new)       |              | Cmd+ / Cmd= / Cmd-  -> PanelSize.stepped
```

## What exists today (read 2026-11-16)

- `PanelController.init` (`Sources/Pauri/PanelController.swift:8-32`) makes `FloatingPanel` with `contentRect` 520 x 680 and style mask `[.nonactivatingPanel, .titled, .fullSizeContentView]`: no `.resizable`. Then `panel.center()`. The panel is not resized or moved anywhere else; `hide()` is `orderOut`, so a hide and a show keep the frame already.
- The SwiftUI content is an `NSHostingView` inside an `NSVisualEffectView` with `autoresizingMask = [.width, .height]`, so the content follows a new window size with no change to `PanelView`.
- Existing key equivalents are SwiftUI `.keyboardShortcut`s: Cmd+K and Cmd+N in `PanelView.swift:81,85`; in `HistoryList.swift:165-181` the arrows, Return, Cmd+Delete, Esc. None uses `=`, `+`, or `-`.
- Saved settings follow `Shortcut.saved(in:)` / `save(to:)` in `Sources/Pauri/HotKey.swift:74-84`: a dictionary in `UserDefaults`, a default when the value is missing or bad. Tests use a throwaway suite (`Tests/PauriTests/ShortcutTests.swift:34-46`).
- **Measured minimum (2026-11-16, throwaway test in a scratch copy, not committed):** `NSHostingController(rootView: PanelView(...)).sizeThatFits(in: .zero)` returned **251 x 156**, with an empty chat, the `Codex default` model label, and no Blossom logo (`swift test` has no app bundle). A 2-line-to-8-line growth of the input `TextField(axis: .vertical).lineLimit(2...8)` measured **32 to 128 pt** (+96).

## Gate 1 decisions (owner: change any of these before go)

1. **Minimum size: 280 x 280 pt.** Width: 251 measured + 25 for the Blossom logo (22 pt frame + 3 pt spacing, `ModelPicker.swift`) = 276, rounded up. Height: 156 measured + 96 for an 8-line draft = 252, + 28 for the transparent title bar's top inset (an assumption, not measured) = 280. At 280 tall, the message area is about 0 pt when the draft has 8 lines, and about 96 pt when it has 2. The build session checks this on the built app; if the header buttons or an 8-line input do not fit, it raises the number and says so at gate 2. Alternative: a larger minimum that keeps a few messages visible, such as 360 x 400.
2. **Maximum size: the `visibleFrame` of the screen the panel is on** (the screen less the menu bar and the Dock). A drag is capped through `windowWillResize`; Cmd+ is capped by the same rule. At launch, a saved size that is too big for the current main screen (a smaller monitor) is cut down to fit.
3. **Step: 52 x 68 pt per press**, one tenth of the default size, so the default is a whole number of steps away from itself and Cmd+ then Cmd- returns to the same size. The step is a guess. From 520 x 680: Cmd+ gives 572 x 748, Cmd- gives 468 x 612. A press that would pass a limit stops at the limit.
4. **Cmd+ and Cmd- keep the panel's top-left corner where it is**, then move the panel only as far as needed to stay on the screen. This is the macOS norm for a window that changes size. Alternative: keep the center fixed, so the panel grows in all directions.
5. **Only the size is saved, not the position.** The panel still opens centered on the main screen at launch, as today. `setFrameAutosaveName` is not used because it also restores the position (issue constraint: do not change where the panel appears).
6. **Cmd+ / Cmd= / Cmd- work wherever focus is in the panel**, including the input and the past-chats search field: the panel takes the key before the text field sees it. With the settings popover open, the popover has focus and the keys do nothing. Holding the key repeats the step.
7. **No resize animation.** `setFrame(_:display:)` with no animation, so a held key never stacks animations.

## Global Constraints

- No visual-rule variants: the panel keeps its look; only its size changes. (#37)
- No text zoom: Cmd+ and Cmd- resize the panel only. (#37)
- Do not change where the panel appears on screen beyond keeping it on the screen after a resize. (#37)
- Do not touch #19's polish work or the update button. (#37)
- 520 x 680 stays the default for a first launch. (#37)
- Public repo: no env values, credentials, or owner personal data in code or commits.

## Review Focus

1. A saved size bigger than today's screen (the user unplugged a large monitor): the panel opens at most screen-sized. Test: `clampedCapsAtScreen` (Task 1).
2. Cmd- at the minimum, or Cmd+ at the screen size: nothing changes, no jump. Tests: `stepStopsAtMinimum`, `stepStopsAtScreen` (Task 1).

### Task 1: The panel size rules

**Files:**
- Create: `Sources/Pauri/PanelSize.swift`
- Test: `Tests/PauriTests/PanelSizeTests.swift`

**Interfaces:**
- Produces (all `static`, on `enum PanelSize`, no `@MainActor` needed):
  - `key: String` = `"panelSize"`
  - `default: CGSize` = 520 x 680; `minimum: CGSize` = 280 x 280; `step: CGSize` = 52 x 68
  - `clamped(_ size: CGSize, to screen: CGSize) -> CGSize`: each side raised to `minimum`, then cut to `screen`. When a screen is smaller than the minimum, the screen wins (the issue: never bigger than the screen).
  - `stepped(_ size: CGSize, by direction: Int, screen: CGSize) -> CGSize`: `size + direction * step`, then `clamped`. `direction` is `1` or `-1`.
  - `frame(_ current: NSRect, resizedTo size: CGSize, within visible: NSRect) -> NSRect`: keeps `current`'s top-left (`minX`, `maxY`), then shifts the rect so it lies inside `visible`. Callers pass a `size` already clamped to `visible.size`.
  - `direction(characters: String?, flags: NSEvent.ModifierFlags) -> Int?`: `1` for `"="` or `"+"`, `-1` for `"-"`, else `nil`. Only when `flags.intersection(.deviceIndependentFlagsMask).subtracting([.shift, .capsLock, .numericPad]) == .command`.
  - `saved(in defaults: UserDefaults) -> CGSize`: the dictionary `{"width": Double, "height": Double}` under `key`, or `default` when missing or bad. Not clamped.
  - `save(_ size: CGSize, to defaults: UserDefaults)`

```swift
private let screen = CGSize(width: 1440, height: 875)

@Test func clampedKeepsSizeInRange() {
    #expect(PanelSize.clamped(CGSize(width: 600, height: 700), to: screen) == CGSize(width: 600, height: 700))
}
@Test func clampedRaisesToMinimum() {
    #expect(PanelSize.clamped(CGSize(width: 100, height: 50), to: screen) == PanelSize.minimum)
}
@Test func clampedCapsAtScreen() {
    #expect(PanelSize.clamped(CGSize(width: 3000, height: 2000), to: screen) == screen)
}
@Test func stepGrowsAndShrinksByOneStep() {
    #expect(PanelSize.stepped(PanelSize.default, by: 1, screen: screen) == CGSize(width: 572, height: 748))
    #expect(PanelSize.stepped(PanelSize.default, by: -1, screen: screen) == CGSize(width: 468, height: 612))
}
@Test func stepStopsAtMinimum() {
    #expect(PanelSize.stepped(PanelSize.minimum, by: -1, screen: screen) == PanelSize.minimum)
}
@Test func stepStopsAtScreen() {
    #expect(PanelSize.stepped(screen, by: 1, screen: screen) == screen)
}
@Test func resizedFrameKeepsTopLeft() {
    let visible = NSRect(x: 0, y: 25, width: 1440, height: 875)
    let current = NSRect(x: 100, y: 100, width: 520, height: 680)   // top at 780
    #expect(PanelSize.frame(current, resizedTo: CGSize(width: 572, height: 748), within: visible)
        == NSRect(x: 100, y: 32, width: 572, height: 748))
}
@Test func resizedFrameStaysOnScreen() {
    let visible = NSRect(x: 0, y: 25, width: 1440, height: 875)
    let nearCorner = NSRect(x: 900, y: 25, width: 520, height: 680)  // right at 1420, bottom on the Dock line
    #expect(PanelSize.frame(nearCorner, resizedTo: CGSize(width: 572, height: 748), within: visible)
        == NSRect(x: 868, y: 25, width: 572, height: 748))
}
@Test func keyDirection() {
    #expect(PanelSize.direction(characters: "=", flags: .command) == 1)
    #expect(PanelSize.direction(characters: "+", flags: [.command, .shift]) == 1)
    #expect(PanelSize.direction(characters: "+", flags: [.command, .numericPad]) == 1)
    #expect(PanelSize.direction(characters: "-", flags: .command) == -1)
    #expect(PanelSize.direction(characters: "-", flags: [.command, .numericPad]) == -1)
    #expect(PanelSize.direction(characters: "=", flags: []) == nil)
    #expect(PanelSize.direction(characters: "=", flags: [.command, .option]) == nil)
    #expect(PanelSize.direction(characters: "k", flags: .command) == nil)
    #expect(PanelSize.direction(characters: nil, flags: .command) == nil)
}
@Test func nothingSavedGivesDefaultSize()   // saved(in: fresh suite) == PanelSize.default
@Test func savedSizeSurvivesRelaunch()       // save(600 x 700) to suite, saved(in: new handle on same suite) == 600 x 700
@Test func badSavedSizeGivesDefault()        // set "big" under key -> default; set ["width": 600.0] -> default
```

### Task 2: Wire the rules into the panel

**Files:**
- Modify: `Sources/Pauri/PanelController.swift` (whole file is 52 lines)
- Modify: `README.md` (one new line in `## Build`, after the `Past chats` line)

**Interfaces:**
- Consumes: everything `PanelSize` produces in Task 1.
- Produces: nothing new for other code. `PanelController`'s public surface (`init(hotKey:chat:updater:)`, `isKey`, `show()`, `hide()`) does not change.

- [ ] **Step 1: Make the panel resizable and open it at the saved size**

In `PanelController.init`: add `.resizable` to the style mask. Set `panel.minSize = PanelSize.minimum` (gives the right resize cursor at the limit). Before `panel.center()`, set the frame size: `PanelSize.clamped(PanelSize.saved(in: .standard), to: NSScreen.main?.visibleFrame.size ?? PanelSize.saved(in: .standard))` (no main screen: skip the screen cap) through `panel.setFrame(NSRect(origin: .zero, size: ...), display: false)`. Work in frame sizes everywhere (not `setContentSize`), so the saved value, the clamp, and the step all use one unit.

- [ ] **Step 2: Make `PanelController` the window delegate**

`PanelController` becomes `final class PanelController: NSObject, NSWindowDelegate` (call `super.init()` after `panel` is set). Set `panel.delegate = self` as the last line of `init`, after `center()`, so the launch sizing does not save. Two methods:
- `windowWillResize(_ sender: NSWindow, to frameSize: NSSize) -> NSSize`: `PanelSize.clamped(frameSize, to: sender.screen?.visibleFrame.size ?? frameSize)`.
- `windowDidResize(_ notification: Notification)`: `PanelSize.save(panel.frame.size, to: .standard)`. This one place saves both a drag and a key step, because `setFrame` also posts it.

- [ ] **Step 3: Handle Cmd+ / Cmd= / Cmd- in `FloatingPanel`**

Override `performKeyEquivalent(with event: NSEvent) -> Bool`: if `PanelSize.direction(characters: event.charactersIgnoringModifiers, flags: event.modifierFlags)` is non-nil, resize and return `true`; otherwise `return super.performKeyEquivalent(with: event)`. The resize: `visible = (screen ?? NSScreen.main)?.visibleFrame`, and with no screen return `true` without resizing; new size `PanelSize.stepped(frame.size, by: direction, screen: visible.size)`; `setFrame(PanelSize.frame(frame, resizedTo: size, within: visible), display: true)`. Checking our keys before `super` is what keeps `=` and `-` out of the text field (decision 6).
