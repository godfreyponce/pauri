# Show That Pauri Is Up To Date Implementation Plan (refs #34)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the feed has no newer version, the user can see that Pauri is up to date and which version runs. When the feed has a newer version, the header up-arrow works exactly as today.

**Architecture:** Task 1 builds `design-directions/issue-34.html` (four shapes for where the status lives) and stops for the owner's pick. Task 2 gives `Updater` an observable `status` and the installed version, fed by Sparkle's end-of-cycle delegate call, plus a `checkNow()` that runs Sparkle's user-initiated check with no Sparkle window. Task 3 wires the picked variant into SwiftUI, updates the README line, and runs the hand check on a local test feed and the full check.

**Tech Stack:** Swift 6, SwiftUI (macOS 14), Sparkle 2.10.1, Swift Testing. One static HTML page. No new dependency.

**Spec:** issue #34. Background: `docs/HISTORY.md` sections #28 (header update button), #32 (panel after an update relaunch), #33 (feed lag; a running Pauri checks again only at relaunch or after 24 hours).

## What exists today (read 2026-11-16)

- `Updater` (`Sources/Pauri/Updater.swift`) is Sparkle's user driver and delegate. It starts only when a feed is set (`PauriChecksForUpdates` in a release build, or the `PauriTestFeedURL` default); a dev build never starts it. At start it calls `checkForUpdatesInBackground()`.
- `showUpdateFound` sets `readyVersion`; `PanelView.swift:59-71` shows the `arrow.up.circle` button only when `readyVersion` is set.
- **The ticket's hook is the wrong one for the launch check.** Sparkle's `SPUUserDriver.h` says `showUpdateNotFoundWithError` tells the user "a new update was not found **after they tried initiating an update check**". A background check never calls it. `SPUUpdaterDelegate.updater(_:didFinishUpdateCycleFor:error:)` is called at the end of every check, and its `error.code` is `SUNoUpdateError` (1001, domain `SUSparkleErrorDomain`) when no update was found.
- `showUpdateInstalledAndRelaunched` runs only in the old process (HISTORY #32), so the new process cannot use it. Since #32, a relaunch after an update opens the panel.
- `SettingsView` (`Sources/Pauri/Settings.swift:11-29`) is a 320 pt `Form` in a popover from the header gear. `EmptyState` (`Sources/Pauri/EmptyState.swift`) is the new-chat screen.
- Style for the page: `design-directions/issue-21.html` (dark page, glass panel on a busy backdrop, state buttons under each variant). The shipped panel is its variant C.

## Gate 1 decisions (owner: change any of these before go)

1. **The pick happens at a stop after Task 1, not at gate 1.** As in #5, #8, #16, #17, #21: after go, the build session builds the page and stops; Tasks 2 and 3 wait for your pick.
2. **References** (for feel, not layout): (a) Pauri's own header and settings popover, as shipped (`design-directions/issue-21.html` variant C); (b) macOS System Settings, General, Software Update, which says the Mac is up to date and names the version; (c) the ChatGPT Mac app on this Mac, which uses Sparkle and has a Check for Updates command. If you want others, send a link or a screenshot in your reply; a screenshot is saved to `docs/reference/` and shown on the page.
3. **The four shapes** (where the status lives):
   - **A. Header icon.** When up to date, a small `checkmark.circle` sits in the up-arrow's slot left of `⌘K`. Its tooltip: `Pauri 0.1.1 is up to date. Checked 2 minutes ago.` A click checks now. When an update is out, the up-arrow takes the slot, as today.
   - **B. Settings line.** The header does not change. The settings popover gets a last row: `Pauri 0.1.1`, then `Up to date, checked 2 minutes ago`, and a `Check now` button.
   - **C. Short notice.** After each finished check, the next time the panel shows, the chat title in the header gives way to `Pauri 0.1.1 is up to date` for a few seconds, then the title comes back. A click on the notice checks again.
   - **D. Empty-state footer.** The new-chat screen gets one quiet line at its bottom: `Pauri 0.1.1, up to date`, then a `Check now` link. During a chat it is not visible; Cmd+N shows it.
4. **A user can start a check by hand, in every variant.** It calls Sparkle's `checkForUpdates()`; Sparkle's windows stay hidden because `Updater` shows nothing. Why: the #33 gotcha, where a running Pauri checks again only at relaunch or after 24 hours. Alternative: no check-now control, which drops `checkNow()` and the Checking state.
5. **No separate "just updated" state.** After an update the relaunched panel opens (#32), the launch check runs, and the status shows the new version as up to date. That answers "did the update work, and am I current". Alternative: an `Updated to Pauri 0.1.2` wording read from #32's relaunch flag, which adds one state.
6. **Five states, one copy each, final wording set by the pick:** updates off (a dev build, or the updater did not start): `Pauri 0.1.0, updates off`; checking: `Checking for updates`; up to date: `Pauri 0.1.1 is up to date` plus the time of the check; couldn't check (offline, feed error, failed download): `Pauri 0.1.1, couldn't check for updates`; update ready: the existing up-arrow, which wins over every other state. "Up to date" never shows unless a check just found nothing.
7. **`SUNoUpdateError` counts as up to date** for every reason Sparkle gives, including "the newest version needs a newer macOS". There is no newer version this Mac can run.

- [ ] **Step 1: Write the failing tests** in `UpdaterTests`:

```swift
@Test func noUpdateMeansUpToDate() {
    let now = Date(timeIntervalSince1970: 1_000)
    let error = NSError(domain: SUSparkleErrorDomain, code: Int(SUError.noUpdateError.rawValue))
    #expect(Updater.status(afterCycleError: error, at: now) == .upToDate(checkedAt: now))
}

@Test func otherErrorMeansCouldNotCheck() {
    let appcast = NSError(domain: SUSparkleErrorDomain, code: Int(SUError.appcastError.rawValue))
    let offline = NSError(domain: NSURLErrorDomain, code: NSURLErrorNotConnectedToInternet)
    #expect(Updater.status(afterCycleError: appcast, at: .now) == .couldNotCheck)
    #expect(Updater.status(afterCycleError: offline, at: .now) == .couldNotCheck)
}

@Test func cleanFinishLeavesStatusAlone() {
    #expect(Updater.status(afterCycleError: nil, at: .now) == nil)
}
```

## #34 Show that Pauri is up to date (2026-11-16)

- Variant A1 of `design-directions/issue-34.html` (the owner picked A, then A1 from four ways
  to thin A's header): with no update ready, a status icon takes the up-arrow's slot, and the
  `⌘K` label next to the search icon is gone. Check mark: up to date. Spinner: checking.
  Exclamation mark: couldn't check (offline, feed error, failed download). Dim dash: updates
  off (dev build). A click on the check mark or the exclamation mark checks now. The up-arrow
  still wins over every other state.
- `Updater` gained `status` (`off`, `checking`, `upToDate(checkedAt:)`, `couldNotCheck`),
  `installedVersion` (`CFBundleShortVersionString`) and `checkNow()`. The status comes from
  `updater(_:didFinishUpdateCycleFor:error:)`: Sparkle's `SUNoUpdateError` (1001) is up to date,
  any other error is couldn't check, and `nil` leaves the status alone.
  `showUpdateNotFoundWithError` fires only for user-started checks, so it could not be the hook.
- `.help` tooltips never show in the panel: AppKit draws tooltips only for the active app, and
  the nonactivating panel never activates Pauri. The status words are a `HoverLabel` the panel
  draws under the icon (`PanelView.swift`); the header has `.zIndex(1)` so the label draws over
  the chat. At the owner's request the up-arrow got the same label, pinned while installing:
  `Updating to Pauri X. Pauri will restart.` Search, new chat and settings still use `.help`,
  which never shows.
- After a Check now click, Checking holds for at least 1 s (`Updater.minimumCheckingTime`, a
  guess): a local feed answers in milliseconds, so without it the spinner never showed and
  every click started a new check.
- Hand check on the local test feed, owner looking and clicking: H2 up to date at 0.1.2 on
  hover; H3 one request per click, spinner then check mark; H4 server stopped, exclamation mark
  and couldn't check (Sparkle error 2001); H5 0.1.0 showed the up-arrow and its hover label,
  one click relaunched 0.1.2 with the panel open and up to date; H6 dev build, dim dash and
  `Pauri 0.1.0, updates off`, no request in 30 s.
- Deferred minors from the final review: a `nil`-error cycle end while Checking would leave the
  spinner on; a hover label may stay up after the panel hides while hovered; the delayed status
  write does not check for a newer cycle; a failed install reads "couldn't check for updates".
