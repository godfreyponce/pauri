# Dictation Button Implementation Plan (refs #11)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mic button in the input bar. Press it to start, press it again to stop. While it listens, the spoken words show in the input box as they are spoken, recognized on this Mac only. First use asks for Microphone and Speech Recognition access; after a no, the panel says how to turn them on. Dictation never sends.

**Architecture:** `Dictation` (new, `@Observable @MainActor`) owns one `AVAudioEngine` input tap feeding one `SFSpeechAudioBufferRecognitionRequest` with `requiresOnDeviceRecognition = true`, and reports each partial transcription to `PanelView` through a callback. `PanelView` keeps the draft as it was before the press (the prefix) and writes `prefix + spoken` into `draft` on each result. A pure function `Dictation.problem(...)` turns the access answers into the one message the panel shows. `Support/Info.plist` gets the two usage-description keys macOS needs before it shows the access dialogs.

**Tech Stack:** Swift 6 (Command Line Tools), SwiftPM, SwiftUI, AppKit, Speech (`SFSpeechRecognizer`), AVFoundation (`AVAudioEngine`, `AVCaptureDevice`), Swift Testing. No third-party dependency.

**Spec:** `docs/spec.md` decision 17; issue #11.

**Probe (2026-11-14, this Mac, macOS 26.5.2):** `SFSpeechRecognizer()` gives locale `en_US`, `isAvailable` true, `supportsOnDeviceRecognition` true. Speech authorization is not determined (0); Terminal's mic status is authorized (3), which says nothing about Pauri's own grant.

```text
   |                                         "Open System Settings" --> x-apple.systempreferences: URL
   v
microphone --reads--> AVAudioEngine.inputNode tap (new)
   |
   v
SFSpeechAudioBufferRecognitionRequest (new, requiresOnDeviceRecognition = true)
   |

   v

```

## Gate 1 decisions (owner: change any of these before go)

1. **No 4-variant visual pass.** The mic is a stock `.borderless` button between the text field and the send orb: SF Symbol `mic` when idle, `mic.fill` in red while listening, `mic.slash` after a refusal. The problem row is plain secondary text with one `.borderless` button, the same look as `SelectionBar`'s access row. Same call as #1, #3, #6, #9, and #12: the look belongs to the spec's Fog item "a design-directions pass once the bones work". Say no here and Task 2 starts with the variants page in `design-directions/issue-11.html`, references first.
2. **Dictation adds to what is already typed.** At the press, the draft is kept as the prefix. Each result sets the draft to the prefix, one space if the prefix does not already end in whitespace, then the spoken text. Alternative: replace the draft with the speech.
3. **Typing while the mic listens stops the mic and keeps what you typed.** Without this, the next spoken word would overwrite the typed letters. Alternative: grey out the text field while listening (simpler, but the box looks disabled while words flow in, and Return stops working).
4. **Stop means stop now.** Pressing the mic again, sending (Return or the orb), or the panel losing key (hotkey hide, Esc, clicking another app, opening the settings popover) stops the audio and drops any result that comes later. The box keeps exactly what was on screen. Alternative: wait for the recognizer's final result after a stop. It can fix the last word's punctuation, but it can land after a send and put the text back into the cleared box.
5. **After a refusal, the panel says what to turn on.** The mic icon becomes `mic.slash`, its tooltip and a one-line row above the input give the message, and an **Open System Settings** button opens the right Privacy pane. Messages:
   - Microphone refused: `Pauri needs Microphone access to dictate. Turn on Pauri in System Settings > Privacy & Security > Microphone.`
   - Speech Recognition refused: `Pauri needs Speech Recognition access to dictate. Turn on Pauri in System Settings > Privacy & Security > Speech Recognition.`
   - No on-device model for the Mac's language: `This Mac cannot recognize speech on-device for your language, so Pauri does not dictate.` (no button)
   - The mic did not start (no input device, or the engine threw): `Pauri could not start the microphone.` (no button)

   The row goes away on the next mic press that works. When both accesses are refused, the Microphone message shows first.
6. **Punctuation on.** `addsPunctuation = true` (macOS 13+), so "fix the bug period" is not needed. Alternative: off, raw words only.
7. **The Mac's language.** `SFSpeechRecognizer()` with no locale uses the system language (en_US here). No language picker.

## Global Constraints

- On-device only (issue Constraints, Done when item 2). `request.requiresOnDeviceRecognition = true` on every request. If `supportsOnDeviceRecognition` is false, do not start; show the gate 1 decision 5 message. No Whisper, no network speech service, no server fallback.
- Nothing in `Dictation` calls `submit()` or `chat.send`. The only paths to a send stay the Return key and the orb (Done when item 4).
- The mic runs only between a press that starts it and a stop (gate 1 decision 4). No dictation at launch, no hotkey to start it.
- **Swift 6 isolation trap.** The `installTap` block (`AVAudioNodeTapBlock`) and the `SFSpeechRecognizer.requestAuthorization` handler are not `@Sendable` in the SDK, and both run off the main thread. Created inside a `@MainActor` method, Swift 6 infers them as main-actor closures and the app crashes at runtime (`dispatch_assert_queue_fail`), not at compile time. Create both in `nonisolated static` functions. Wrap `requestAuthorization` in `withCheckedContinuation` there. The recognition-task handler: create it in a `nonisolated static` function too, read `result.bestTranscription.formattedString`, `result.isFinal`, and `error != nil` inside it, and hop to the main actor with `Task { @MainActor in ... }` carrying only those values (`SFSpeechRecognitionResult` is not `Sendable`).
- Check `inputNode.outputFormat(forBus: 0).sampleRate > 0` before `installTap`. A zero rate (no input device) makes `installTap` raise an Objective-C exception that Swift cannot catch.
- No `NSApp.activate` (#1). The macOS access dialogs come from the system and need no activation.
- Test files import `AppKit`, not `Foundation`. Command Line Tools have no `_Testing_Foundation` overlay (#12 history).
- Public repo: no transcription text in `NSLog`.
- Commit format: `type(scope): summary (refs #11)`. Trailers: the harness default `Co-Authored-By` line, nothing else.

**Interfaces:**
- Produces:
  - `enum DictationProblem: Equatable { case microphone, speechRecognition, noOnDeviceModel, couldNotStart }` with `var message: String` (texts exactly as in gate 1 decision 5) and `var settingsURL: URL?`: `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone` for `.microphone`, `x-apple.systempreferences:com.apple.preference.security?Privacy_SpeechRecognition` for `.speechRecognition`, nil for the other two.

    - `nonisolated static func problem(micAllowed: Bool, speechAllowed: Bool, onDevice: Bool) -> DictationProblem?`. Checked in that order; all true gives nil.
    - `nonisolated static func makeRequest() -> SFSpeechAudioBufferRecognitionRequest` with `requiresOnDeviceRecognition = true`, `shouldReportPartialResults = true`, `addsPunctuation = true`.

### Task 2: The mic listens; the input bar shows it

**Files:**
- Modify: `Sources/Pauri/Dictation.swift` (engine, access, start, stop)
- Modify: `Sources/Pauri/PanelView.swift` (mic button, problem row, prefix, stops)
- Modify: `Support/Info.plist` (two usage-description keys)
- Modify: `README.md` (`## Build`, `## Status`)

**Interfaces:**
- Consumes (Task 1): `Dictation.joined`, `Dictation.problem`, `Dictation.makeRequest`, `DictationProblem`.
- Produces, on `Dictation`:
  - `private(set) var isListening = false`, `private(set) var problem: DictationProblem?`.
  - `func start(onText: @escaping @MainActor (String) -> Void)`. Clears `problem`, then in a `Task`: `await AVCaptureDevice.requestAccess(for: .audio)`; the speech answer from a `nonisolated static func requestSpeechAccess() async -> Bool` (continuation around `SFSpeechRecognizer.requestAuthorization`, true only for `.authorized`); `onDevice = SFSpeechRecognizer()?.supportsOnDeviceRecognition ?? false`. If `problem(...)` is non-nil, set it and return. Otherwise build `AVAudioEngine`, check the sample rate (Global Constraints), install the tap (block from a `nonisolated static` function that calls `request.append(buffer)`), `engine.prepare()`, `try engine.start()` (on throw: stop, `problem = .couldNotStart`), start the recognition task (handler from a `nonisolated static` function), set `isListening = true`. Each result calls `onText(spoken)` on the main actor unless the run was stopped. An error or `isFinal` calls `stop()`.
  - `func stop()`. Idempotent. Stops the engine, removes the tap, `request.endAudio()`, `task.cancel()`, drops the callback so a late result writes nothing, sets `isListening = false`. Keeps `problem`.
  - No `toggle` that knows the draft: `PanelView` owns the prefix.
- `PanelView` changes:
  - `@State private var dictation = Dictation()` and `@State private var dictationPrefix = ""`.
  - `submit()` calls `dictation.stop()` first, then sends as today.
  - Mic button in the input `HStack`, between the `TextField` and `SendOrb`. Action: if listening, `dictation.stop()`; else `dictationPrefix = draft`, then `dictation.start { draft = Dictation.joined(dictationPrefix, $0) }`. Icon per gate 1 decision 1 (`.foregroundStyle(.red)` only while listening). `.help`: `Dictate` idle, `Stop dictation` while listening, `problem.message` after a problem.
  - `.onChange(of: draft)`: if listening and the new value is not the last text dictation wrote, `dictation.stop()` (gate 1 decision 3). Keep the last written text in a `@State` set inside the `onText` closure, so the check compares against it.
  - The key-loss stop: a second `.onReceive` for `NSWindow.didResignKeyNotification` where `note.object is FloatingPanel` calls `dictation.stop()`.
  - Problem row, directly above `SelectionBar(chat: chat)`: when `dictation.problem` is set, an `HStack` with the message in `.secondary`, a `Spacer`, and, if `settingsURL` is set, a `.borderless` **Open System Settings** button calling `NSWorkspace.shared.open(url)`.
- `Support/Info.plist` adds:
  - `NSMicrophoneUsageDescription`: `Pauri listens only while the mic button is on, and types what you say into the question box.`
  - `NSSpeechRecognitionUsageDescription`: `Pauri turns your speech into text on this Mac. Nothing is sent to a server.`
