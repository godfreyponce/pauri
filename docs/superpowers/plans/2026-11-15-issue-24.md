# Send Waits While the Open Chat Is Deleted Implementation Plan (refs #24)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While the open chat is being deleted, `Chat.send` refuses and the send orb is off, so a question can never go to the deleted thread; after the delete the next question starts a new thread.

**Architecture:** A new `Chat.isDeletingOpenChat` flag, set by `Chat.delete(_:)` only when the thread being deleted is the open one, and cleared by a `defer` when the delete returns or throws. `send` refuses while it is set, the same way it refuses while `isOpening` (#20). The send orb's `isEnabled` in `PanelView` reads it too. The flag is **not** added to `canStartNewChat` (see Global Constraints), so `delete` can still call `newChat()` while the flag is set.

**Tech Stack:** Swift 6, SwiftPM, SwiftUI (macOS 14), Swift Testing. No new dependency.

**Spec:** issue #24 (no design spec).

## Data flow

No data-flow change: only the guard logic inside `Chat` and the orb's enabled state change; `thread/delete`, `turn/start`, and the remembered ID list are read and written as before.

## Global Constraints

- No change to the two-press delete or to the palette's look (#22). (issue #24, Constraints)
- No new chat store; the remembered ID list from #20 stays the only one. (issue #24, Constraints)
- **Gate 1 decision: `isDeletingOpenChat` stays out of `canStartNewChat`.** Putting it there would also dim the palette's rows and footer keys (`HistoryList.swift:145`, `:171`, `:179` read `canStartNewChat`) for the length of the delete, which is a palette look change the ticket forbids, and `delete` would then have to clear the flag before its own `newChat()`. The palette already blocks open and a second delete with its own `isDeleting`. The panel's New chat button (Cmd+N) stays live during the delete; pressing it then only forgets a thread that is being deleted anyway, and the delete's own `newChat()` runs after it.
- **Gate 1 decision: only a delete of the open chat sets the flag.** Deleting another chat cannot send to the wrong thread, so the orb stays on for it.
- No visual-rule variants: the orb uses its existing disabled look; no shape or layout changes.
- Public repo: no env values, credentials, or owner personal data in code, tests, or commits.

## Review Focus

2. **The first question after the delete.** Expected: an empty "New chat", then the question goes to a new thread, not the deleted one, and gets an answer. Same live test.

The `defer` that clears the flag runs on a throw, and `newChat()` still runs only after `client.delete` returns; gate 2 checks this by reading the diff.
4. **Deleting a chat that is not open.** Expected: the orb stays on and the open chat is untouched. Covered by the existing live test `liveDeleteDropsTheChatAndTheOpenOneStartsNew` (its first delete), which must still pass.
5. **The orb after the delete.** Expected: the orb turns back on as soon as the delete ends, with text in the box. Hand check in Task 1, Step 6.

```swift
@Test(.enabled(if: ProcessInfo.processInfo.environment["PAURI_LIVE"] == "1"))
@MainActor func liveSendWaitsWhileTheOpenChatIsDeleted() async throws {
    let client = CodexClient(defaults: freshDefaults("pauri-live-delete-send"))
    let chat = Chat(client: client)
    chat.warmUp()
    try await waitUntil { !chat.isStarting }
    #expect(chat.send("what is 2+2"))
    try await waitUntil { !chat.isAnswering }
    let open = try #require(client.threadID)

    let deleting = Task { try await chat.delete(open) }
    // Main actor: one yield runs the delete up to its wait on Codex's reply.
    await Task.yield()
    #expect(chat.isDeletingOpenChat)
    #expect(!chat.send("what is 3+3"))
    try await deleting.value

    #expect(!chat.isDeletingOpenChat)
    #expect(chat.exchanges.isEmpty)
    #expect(client.threadID == nil)
    #expect(chat.send("what is 5+5"))
    try await waitUntil { !chat.isAnswering }
    let next = try #require(client.threadID)
    #expect(next != open)
    #expect(chat.exchanges.count == 1)
    #expect(chat.exchanges[0].answer.contains("10"))
    try await quit(client)
}
```
