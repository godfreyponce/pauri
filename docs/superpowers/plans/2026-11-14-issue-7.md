# Screenshot Button Implementation Plan (refs #7)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A button in the input bar takes one screenshot of the screen the panel is on, without Pauri's own windows in it, and shows it as a thumbnail chip above the input. The next send passes the image to Codex with the question. The first press asks macOS for Screen Recording access; after a no, the panel says how to turn it on. Nothing captures without a press.

**Architecture:** `ScreenCapture` (new, `Sources/Pauri/ScreenCapture.swift`) checks and requests Screen Recording access (`CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess`), takes one image with ScreenCaptureKit's `SCScreenshotManager.captureImage` using a filter that excludes Pauri's own app, and writes it as a PNG to the temp folder. `Chat` holds the attached file's URL (like `selection`), and `send` passes it to `CodexClient.ask(_:image:)`. `CodexClient` adds a `{"type": "localImage", "path": ...}` item after the text item in `turn/start`. `Chat` deletes the file when the answer's stream ends, or when the chip is removed or replaced. `ScreenshotChip` (new) shows the thumbnail.

**Tech Stack:** Swift 6 (Command Line Tools), SwiftPM, SwiftUI, AppKit, ScreenCaptureKit (`SCShareableContent`, `SCContentFilter`, `SCScreenshotManager`, macOS 14+, which `Package.swift` already targets), CoreGraphics, ImageIO, Swift Testing. No third-party dependency.

**Spec:** `docs/spec.md` decision 10; issue #7.

**Probe (2026-11-14, this Mac, codex-cli 0.169.0), answering the issue's Constraint:** `codex app-server` takes image input. The generated protocol (`codex app-server generate-ts`) has `UserInput` variant `{ type: "localImage", path: string, detail?: ImageDetail }` on `turn/start`. A live probe sent a 64x64 PNG (left half red, right half blue) as `localImage` on an ephemeral thread with the text "What two colors are in the attached image, left then right?". The turn completed and Codex answered `Red, blue.` Codex's saved session files store a sent image inline as `"input_image","image_url":"data:image/png;base64,..."`, so the thread keeps the image after Pauri deletes its file. Task 1's live test proves that on a real follow-up. The plan does not stop for the owner.

## Gate 1 decisions (owner: change any of these before go)

1. **No 4-variant visual pass.** The button is a stock `.borderless` button with SF Symbol `camera.viewfinder`, placed left of the mic. The chip copies `SelectionBar`'s chip: a capsule-shaped `.quaternary` background with a small thumbnail, the word `Screenshot`, and an x. The problem row copies the dictation row. Same call as #1, #3, #6, #9, #11, and #12: the look belongs to the spec's Fog item "a design-directions pass once the bones work". Say no here and Task 2 starts with the variants page in `design-directions/issue-7.html`, with references first.
2. **The screen the panel is on, at its point size.** The capture is the display that holds the panel (main display if that cannot be found), at the display's size in points, not Retina pixels, with no cursor. Reason for points: Codex's model gets a downsized image anyway. OpenAI's vision guide scales high-detail images to fit 2048x2048, then the short side to 768 px. That is from memory and not checked here. A typical MacBook screen in points (1512x982) is already under that. Points also give a smaller PNG to write and to embed in the session file. Alternative: full Retina pixels.
3. **Pauri's own windows are left out by the filter, not by hiding the panel.** `SCContentFilter(display:excludingApplications: [Pauri], exceptingWindows: [])`. The panel stays on screen and nothing flickers. This also drops the settings popover.
4. **One screenshot at a time.** A second press replaces the chip and deletes the old file. Selected text and a screenshot can go together in one send.
5. **A question is still needed.** The orb stays disabled with an empty input, as today. A screenshot alone does not send. Alternative: allow an image-only send with no text.
6. **The file lives only until the answer ends.** The PNG is written to `$TMPDIR/pauri-screenshot-<UUID>.png`. `Chat` deletes it when the turn's stream ends (done, stopped, or failed), or when the chip is removed or replaced. If Pauri quits with an unsent chip, the file stays in the temp folder until macOS clears it. Codex keeps its own copy inside the session file (Probe).
7. **Access, first press and after a no.** If `CGPreflightScreenCaptureAccess()` is false, the press calls `CGRequestScreenCaptureAccess()`. The first time ever, that shows the macOS dialog. Then the panel shows this row, with an **Open System Settings** button for `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`:
   `Pauri needs Screen Recording access to attach a screenshot. Turn on Pauri in System Settings > Privacy & Security > Screen & System Audio Recording, then quit and reopen Pauri.`
   The button's tooltip says the same. The row shows right after the first press too, because macOS applies a new grant only after a relaunch (Review Focus 1). If the capture itself throws, the row says `Pauri could not take the screenshot.`, with no button. The next press that works clears the row.
8. **The sent question shows a small marker.** A sent turn with a screenshot gets one `.secondary` line, `photo` symbol plus `Screenshot`, above the question text (`Exchange.hasScreenshot`). Turns restored from a saved thread show no marker: the resume parser stays text-only. Alternative: no marker at all.

## Global Constraints

- **The only call to `ScreenCapture.capture` is the button's action** (Done when item 4). No capture at launch, on the hotkey, or on send. No ScreenCaptureKit call (`SCShareableContent` included) runs before `CGPreflightScreenCaptureAccess()` returns true, because on recent macOS the first `SCShareableContent` call can itself prompt.
- Codex input order: the text item first, then the `localImage` item. Path is the file's `path`, absolute.
- **Swift 6 isolation.** Do the whole ScreenCaptureKit call (`SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)`, filter, `SCStreamConfiguration`, `SCScreenshotManager.captureImage`, PNG write) inside one `nonisolated static func ... async throws -> URL`. Only the `URL` crosses back to the main actor. SC types are not all `Sendable`, and #11 showed that SDK callbacks made on the main actor can crash at runtime, not at compile time.
- No `NSApp.activate` (#1). The macOS dialog comes from the system.
- No usage-description key in `Support/Info.plist`: macOS has none for Screen Recording.
- Test files import `AppKit`, not `Foundation` (Command Line Tools have no `_Testing_Foundation` overlay, #12 history).
- Public repo: no screenshot content, and no file path with a user name, in `NSLog` or in commits.
- Commit format: `type(scope): summary (refs #7)`. Trailers: the harness default `Co-Authored-By` line, nothing else.

## Review Focus

1. **When a new grant takes effect.** On most macOS versions, Screen Recording turned on in System Settings applies only after Pauri relaunches, and System Settings offers "Quit & Reopen". This Mac runs macOS 26 (Darwin 25.5). Expected: after the grant and a relaunch, the press captures. Report at gate 2 whether the press worked without a relaunch, so the row's wording can be fixed if wrong. Hand check 2.
2. **Every rebuild may lose the grant** (STATE.md ad-hoc signing gotcha). Expected: after a rebuild, the press shows the access row and does not crash. Reset with `tccutil reset ScreenCapture io.github.godfreyponce.pauri`. Report what macOS did. Hand check 6.
3. **Pauri is not in the shot.** The filter excludes Pauri by `processID == getpid()` in `SCShareableContent.applications`. If Pauri is missing from that list (it is an `LSUIElement` app with a non-activating panel), the filter excludes nothing and the panel appears in the image. Hand check 3 opens the PNG before sending to look.
4. **The periodic macOS re-confirmation.** macOS 15 and later can ask again ("... is requesting to bypass the system private window picker") for apps that capture without the picker. Expected: a press after that prompt works if the user allows. Not forced; note at gate 2 if seen.
5. **#4 (model picker) is in flight in its own worktree.** A model whose `inputModalities` lacks `"image"` would fail on an image turn. Out of scope here; noted for #4 and the landing notes.

**Interfaces:**
- Consumes (Task 1): `CodexClient.ask(_:image:)`, `ScreenCapture.writePNG`.
- `ScreenCapture.swift` adds:
  - `enum ScreenCaptureProblem: Equatable { case screenRecording, couldNotCapture }` with `var message: String` (texts exactly as in gate 1 decision 7) and `var settingsURL: URL?` (`x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture` for `.screenRecording`, nil for `.couldNotCapture`).
  - `static var isAllowed: Bool { CGPreflightScreenCaptureAccess() }` and `static func requestAccess() { _ = CGRequestScreenCaptureAccess() }`.
  - `static func displayID(of screen: NSScreen?) -> CGDirectDisplayID`: `screen?.deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as? CGDirectDisplayID`, else `CGMainDisplayID()`.
  - `nonisolated static func capture(displayID: CGDirectDisplayID) async throws -> URL`. Gets `SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)`. Picks the display whose `displayID` matches, else the first. Excludes `content.applications.filter { $0.processID == getpid() }`. `SCStreamConfiguration` gets `width = display.width`, `height = display.height` (points, gate 1 decision 2) and `showsCursor = false`. Calls `SCScreenshotManager.captureImage(contentFilter:configuration:)`, then `writePNG` to `FileManager.default.temporaryDirectory.appending(path: "pauri-screenshot-\(UUID()).png")`. Returns the URL.
- `Chat` adds:
  - `private(set) var screenshot: URL?`
  - `func attachScreenshot(_ url: URL)`: deletes the current file if any, then sets `screenshot`.
  - `func removeScreenshot()`: deletes the file, sets nil.
  - `send`: if `screenshot` is set, takes it and sets `screenshot = nil` without deleting, appends the exchange with `hasScreenshot: true`, calls `client.ask(prompt, image: image)`, and after the `for try await` loop and its `catch` (the place that already sets `isAnswering = false`) runs `try? FileManager.default.removeItem(at: image)`. Without a screenshot, `send` behaves as today.
  - `Exchange` gets `var hasScreenshot = false`, after `steps`, so every existing `Exchange(question:answer:)` call still compiles.
  - `newChat()` leaves `screenshot` alone, as it leaves `selection`.
- `ScreenshotChip.swift`: `struct ScreenshotChip: View { let url: URL; let remove: () -> Void }`. It shows `NSImage(contentsOf: url)` as `Image(nsImage:).resizable().scaledToFit()` at a height of 24 pt (a look choice, matched to the chip's text line), then `Text("Screenshot")`, then an x button (`xmark.circle.fill`, `.borderless`, `.help("Remove")`). Same padding, `.quaternary` capsule background, and leading frame as `SelectionBar`'s chip.
- `PanelView` adds:
  - `@State private var screenshotProblem: ScreenCaptureProblem?` and `@State private var isCapturing = false`.
  - A screenshot button in the input `HStack`, after the `TextField`, before the mic. Its action: if `!ScreenCapture.isAllowed`, call `ScreenCapture.requestAccess()`, set `screenshotProblem = .screenRecording`, and return. Otherwise set `screenshotProblem = nil` and `isCapturing = true`. Then, in a `Task`, read the display ID from `NSApp.windows.first { $0 is FloatingPanel }?.screen`, `try await ScreenCapture.capture(displayID:)`, and pass the URL to `chat.attachScreenshot`. On a throw, set `.couldNotCapture`. Always set `isCapturing = false`. `.disabled(isCapturing)`. `.help`: `screenshotProblem?.message ?? "Attach a screenshot"`.
  - A problem row for `screenshotProblem`, directly below the dictation problem row, in the same shape: message in `.secondary`, `Spacer`, and **Open System Settings** if `settingsURL` is set.
  - `if let url = chat.screenshot { ScreenshotChip(url: url) { chat.removeScreenshot() } }` directly above `SelectionBar(chat: chat)`.
  - In the exchange `VStack`, above `Text(exchange.question).bold()`: when `exchange.hasScreenshot`, `Label("Screenshot", systemImage: "photo").foregroundStyle(.secondary)`.
