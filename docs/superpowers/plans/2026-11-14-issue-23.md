# Model Picker Label Without "GPT" Implementation Plan (refs #23)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The model picker's button and its menu rows show a model's name without a leading "GPT-" / "GPT ", so "GPT-6.1-Sol Fast" next to the OpenAI logo reads "6.1-Sol Fast". The name sent to Codex does not change.

**Architecture:** One pure function, `ModelPicker.label(_:)` in `Sources/Pauri/ModelPicker.swift`, turns an optional display name into the shown text. The button (`chat.model?.name`, line 36) and each menu row (`choice.name`, line 32) both call it. `ModelChoice` is not touched: `name` stays the real display name, and `turn/start` keeps sending `ModelChoice.model` (the id), which never went through the label.

**Tech Stack:** Swift 6, SwiftPM, SwiftUI, Swift Testing.

**Spec:** issue #23 (no design spec).

## Data flow

No data-flow change: only the text the picker draws changes; `model/list` in, `turn/start` out, and every file read or written stay the same.

## Global Constraints

- No other picker change: #17's logo, effort bars, and layout stay (issue #23, Constraints).
- The model's real name stays as it is everywhere it is sent to Codex. Only the shown label changes.
- No visual-rule variants: the owner already fixed the exact text ("6.1-Sol Fast"), and nothing about shape or layout changes. (Gate 1 decision.)

## Review Focus

1. A name that is only "GPT" or "GPT-": stripping would leave an empty button. Expected: the name shows unchanged. Pinned by `labelKeepsANameWithNothingAfterGPT`.
2. Lowercase "gpt-5.1-codex" (Codex has reported lowercase display names before). Expected: "5.1-codex", the logo says "OpenAI" either way. Pinned by `labelDropsGPTInAnyCase`. (Gate 1 decision: case-insensitive.)
3. "GPT" inside a name, not at the start ("ChatGPT-5", "Codex GPT"). Expected: unchanged. Pinned by `labelKeepsNamesWithoutALeadingGPT`.
4. Checked-state after a pick: the menu's `Toggle` still binds by `choice.id`, so the label change cannot uncheck the current model. Not a new test; the binding line keeps `chat.model?.id == choice.id` as is.
5. The full id still goes to `turn/start`. Covered by the existing tests `turnStartParamsCarryTheSteppedEffort`, `defaultModelWithoutFastTierSendsNoTier`, and `turnWithNoModelSendsNoModelFields` in `Tests/PauriTests/CodexProtocolTests.swift`; they must pass unchanged.
